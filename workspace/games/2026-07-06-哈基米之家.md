## 〇、方向收敛

三轮讨论后达成的共识：

```
v1: 大规模育种工厂（Factorio 猫版）—— 太庞大
v2: 2h 迷你育种 + 行为编程（D 方案）—— 育种仍有孟德尔包袱
v3: 行为编程沙盒（猫外观 = 组合生成，猫行为 = 可编程）← 当前
```

**一句话**：玩家获得一只外观可定制、行为可编程的猫。通过任务引导学习编程积木，通过观察发现意外的行为涌现。分享有趣的"猫 bug"到社区。

育种退到后台作为外观生成工具（"我想要三花长毛猫"→系统告诉你怎么配→自动完成）。**行为编程是游戏本身。**

### 核心循环

```
┌──────────────────────────────────────────────┐
│                                              │
│   编辑行为积木                                │
│      ↓                                       │
│   观察猫执行                                  │
│      ↓                                       │
│   发现意外行为 / 不符合预期                     │
│      ↓                                       │
│   调试：改一个积木                             │
│      ↓                                       │
│   观察新结果 → 更意外的涌现...                 │
│      ↓                                       │
│   截图/GIF → 分享                             │
│                                              │
└──────────────────────────────────────────────┘
```

**"修好一个 bug → 产生三个新 bug"是这个循环的核心乐趣所在。**

类比 ONI 的 SPOM 或 Factorio 的品质升级循环——设计师给了积木，玩家发现了设计师没预料到的组合。

## 一、核心系统：行为编程

### 1.1 设计哲学

```
简单规则 + 可组合 = 复杂行为涌现

反对：
✗ 图灵完备的编程语言
✗ 每种行为都需要手写脚本
✗ 玩家需要理解"程序"才能玩

支持：
✓ 5-10 个基础行为积木
✓ 积木可以组合/嵌套/并行
✓ 组合后产生设计者自己也想不到的结果
✓ 猫自身的"性格倾向"作为隐藏参数影响执行
```

### 1.2 积木类型（初始探索版，待 Demo 验证后精简）

#### 第一层：基础动作（原子积木）

```
🏃 走到 (目标)       — 移动到指定位置/物体
👅 舔毛              — 自我清洁，持续 2-5 秒
😴 睡觉              — 原地睡眠，持续 N 秒
🍽 进食              — 走向食盆并进食
🐁 攻击/扑 (目标)    — 扑向指定物体
🗣 叫 (类型)         — 喵/咕噜/哈气
👀 注视 (目标)       — 盯着目标，头部跟踪
✋ 触碰 (目标)       — 用爪子触碰
⬆ 跳跃 (目标)       — 跳到指定位置
```

#### 第二层：控制流（组合积木）

```
🔁 重复 (N次)       — 循环执行子积木
🔀 随机选择          — 从多个分支中随机选一个执行
⏱ 等待 (N秒)        — 暂停
🚦 条件              — IF(传感器条件) THEN(动作)
   ├─ 看见 (物体)
   ├─ 听见 (声音)
   ├─ 饥饿 > 阈值
   ├─ 无聊 > 阈值
   ├─ 被触摸
   └─ 时间 (几点钟)
```

#### 第三层：性格修饰符（不直接编程，来自育种）

```
性格参数（0.0 ~ 1.0，育种决定，编程界面可查看但不可直接修改）：

- 胆量：影响"看见新物体"的反应（0=逃跑, 1=凑近探索）
- 精力：影响动作频率和持续时间
- 好奇心：影响"随机选择"的权重分布，改变对陌生刺激的响应概率
- 社交性：影响"被摸"后的反应（0=哈气, 1=呼噜蹭）
- 贪食：影响"看见食物"的行为优先级
- 智力：影响行为执行的"巧妙程度"——高智力猫可能用工具、绕路、等待时机
```

**性格参数是"规则之外的另一只手"** ——同样的行为积木组合，不同性格的猫执行效果完全不同。这是可观察、可比较的乐趣来源。

### 1.3 行为模型：分层优先级 + 有限状态机（技术选型探索）

暂不需要实现，但作为讨论基础。猫行为研究中有几个经典框架：

**参考：《Cat Behavior》（Bradshaw, 2012）— 家猫行为时间预算**：

| 行为 | 占比 |
|------|:--:|
| 睡眠/休息 | 50-70% |
| 梳理（舔毛） | 10-15% |
| 觅食/进食 | 5-10% |
| 探索/巡逻 | 5-10% |
| 社交（蹭/舔其他猫） | 2-5% |
| 玩耍/捕猎练习 | 2-5% |

游戏内的实现方向（待 Demo 验证）：

```
优先级系统（自上而下）：

P0 即时反应（不可被编程覆盖）
  ├─ 惊吓（突然巨响 → 弹跳+逃跑）
  ├─ 疼痛（被踩尾巴 → 尖叫+逃跑）
  └─ 极度饥饿（生命威胁 → 无视一切去找食物）
  
P1 生理需求（可被编程延迟但不能永久忽略）
  ├─ 饥饿 → 进食
  ├─ 排泄 → 猫砂盆
  └─ 疲劳 → 睡眠

P2 本能行为（默认存在，可被编程覆盖）
  ├─ 舔毛（无聊/饭后触发）
  ├─ 巡逻（探索领地）
  └─ 捕猎练习（看见移动小物体）

P3 编程行为（玩家的行为积木）
  └─ 玩家设计的行为序列和条件规则

P4 性格修饰（育种决定的倾向）
  └─ 调整 P1-P3 中所有行为的触发阈值和持续时间
```

这个分层模型的价值在于：**玩家编的程序运行在 P3 层，但 P0-P2 的生理/本能行为会"打断"或"扭曲"程序的执行。** 这种"不完全可控"是有趣行为涌现的关键。

### 1.4 行为 Bug 涌现机制

为什么同样的积木组合，有时候产生有趣的结果？

```
案例：玩家设置 "每隔 30 秒 → 舔毛"

正常执行：猫每 30 秒舔一次毛

意外情况 A：猫在舔毛时
  → P2 巡逻触发（看见窗外一只鸟）
  → 猫中断舔毛，跑去窗边
  → 舔毛计时器在中断时未重置
  → 巡逻回来 → 立即再次舔毛（只过了 15 秒）
  → 玩家观察到："猫突然开始疯狂舔毛"
  → 这是一个 bug！一个可爱的 bug！

意外情况 B：重复执行 + 对象错误
  → 舔毛时碰倒了旁边的杯子
  → 杯子发出声音 → 触发"惊吓"
  → 惊吓 → 逃跑 → 撞到另一只猫
  → 另一只猫哈气 → 第一只猫困惑
  → 玩家截取这个 3 秒的混乱 → 分享

意外情况 C：性格干扰
  → 高好奇心的猫在执行"走到食盆"时
  → 路过一个纸箱 → 条件"看见新物体"触发
  → 猫改变目标 → 钻进纸箱
  → 食盆计划被完全遗忘
  → 玩家："我只是想让猫吃饭…"
```

**关键设计原则**：不把"中断"视为 bug——把它视为内容生成。编程不是为了让猫完全按指令行动，而是为了**创造发生意外的条件**。

## 二、猫外观系统（组合式，非谜题型）

### 2.1 定位

外观是**创作工具**而非**谜题挑战**。

玩家想要一只特定的猫 → 游戏告知需要什么父母 → 玩家获取/培育 → 得到目标猫。

遗传学作为不可见的引擎运行，前台只展示"配方"和"进度"。

### 2.2 外观参数空间

| 维度 | 参数 | 变化范围 |
|------|------|:--:|
| 基础毛色 | 黑/橘/白/灰/棕/… | 8-12 种 |
| 花纹 | 纯色/虎斑(鲭鱼/经典/点状)/玳瑁/三花/重点色 | 6-8 种 |
| 毛长 | 短/中/长/卷 | 3-4 种 |
| 白斑 | 无/少/中/多 | 4 级 |
| 眼睛 | 颜色+形状 | 6 色 × 3 形 |
| 耳朵 | 立/折/卷/大 | 4 种 |
| 体型 | 纤细/标准/壮实/圆润 | 4 种 |
| 尾巴 | 长/短/蓬松/无/卷 | 5 种 |

组合空间：12×7×4×4×(18×3)×4×4×5 ≈ 约 1500 万种外观组合。

### 2.3 美术策略（关键瓶颈）

你提到"美术是一个问题"。对于外观组合爆炸，几种策略：

**策略 A：纸面手绘 + 图层叠加**（推荐）
- 基础猫身 1 张 + 毛色叠加层 + 花纹叠加层 + 白斑面具 + 眼睛变体 + 耳朵变体
- 类似 Paper Mario 的风格——每个部件是独立绘制的，程序化叠加
- 优势：一人可做，不需要 3D 建模
- 劣势：动画帧需要适配所有变体（但其实可以用骨骼动画+部件替换）

**策略 B：Lowpoly 3D + 程序化材质**
- 1 个基础猫模型 + 材质参数（毛色、花纹 UV、眼睛色）
- 动画只需做一次，所有猫共享骨骼
- 优势：动画工作流简单
- 劣势：需要 3D 建模+材质调优

**策略 C：像素风 + 调色板**
- 猫是 32×32 或 64×64 的像素精灵
- 毛色通过调色板替换实现
- 优势：最快出原型
- 劣势：细节表现力受限

**对于 Demo**：策略 C 最快。验证行为编程循环后再决定最终风格。

玩家点击"我要一只三花长毛蓝眼睛的猫"：

```
┌─────────────────────────────────────────┐

## 三、任务/引导系统

### 3.1 "特定猫猫需求任务"如何引导行为编程

不使用教程弹窗。用**猫的"需求"**驱动玩家学习：

```
任务链 1："这只猫好无聊"（入门）

场景：玩家得到第一只猫
观察：猫在房间里走来走去，偶尔舔毛，然后发呆
提示："咪咪看起来有点无聊…要不要加个玩具？"
操作：玩家放置[毛线球] → 猫自动走去触碰
提示："你可以教咪咪怎么玩！打开行为编辑器试试"
操作：玩家进入行为编辑器，看到默认积木：

  [定时 30s] → [随机选择: 舔毛/睡觉/巡逻]

操作：玩家拖入 [条件: 看见 毛线球] → [攻击/扑]
结果：猫现在看到毛线球就会扑上去
反馈：弹出成就 "🎉 第一次编程！"
```

```
任务链 2："为什么猫不吃饭了？"（调试入门）

场景：玩家已经设置了几条行为规则
问题：猫一直蹲在窗边看鸟，食盆满了但不去吃
观察：玩家发现 [条件: 看见 鸟] → [注视 鸟] 的优先级
      高于 [条件: 饥饿>50%] → [进食]
提示："咪咪看鸟看得太专心了…试试调整优先级？"
操作：玩家把进食规则的优先级调高
结果：猫终于去吃饭了——但吃完又立刻回窗边
```

```
任务链 3："折耳猫的秘密"（叙事事件）

触发：玩家获得一只折耳猫
几天后：弹出通知 "咪咪走路姿势有点奇怪…"
观察：猫跛行，跳跃困难
兽医诊断：软骨发育不良——折耳基因纯合导致
知识解锁：基因面板显示 FF vs Ff vs ff
伦理选择：玩家决定以后只让折耳×立耳配对
奖励：解锁"健康猫舍"成就 + 新行为积木"温柔互动"
```

### 3.2 任务类型汇总

| 类型 | 例子 | 教学目的 |
|------|------|---------|
| 观察引导 | "猫一直发呆" | 引导注意行为状态 |
| 功能引入 | "试试加个玩具" | 解锁新积木类型 |
| 调试挑战 | "猫不吃饭了" | 教优先级/冲突解决 |
| 创作目标 | "让猫表演一段 5 秒的节目" | 引导自由创作 |
| 叙事事件 | 折耳猫的故事 | 情感+知识 |
| 社区复现 | "你能复现这个猫meme吗？" | 激发创意 |

## 五、规模与体量

### 5.1 当前定位

```
核心体验时长：1-3h（解锁主要行为积木 + 完成叙事事件 + 创作至少一个节目）
扩展内容：分享社区、成就收集、稀有外观育种、行为编程深度挑战
猫的数量：1-5 只同时在场（单猫深挖 > 多猫浅显）
```

### 5.2 "单猫就够了"的论证

如果行为系统足够深，一只猫可以：
- 有 20+ 个可编辑的行为规则
- 与 15+ 种环境物互动（玩具、家具、其他猫、窗外、食物、声音源）
- 性格参数作为隐藏变量，同一套规则在不同猫身上表现不同
- 玩家换一只猫（不同外观+不同性格）→ 重新编辑行为 → "新游戏+"体验

类比：Tamagotchi 只有一只宠物，但观察和互动足以支撑数周的参与度。

### 5.3 Demo 建议（你提到的探索）

```
Demo v0.1 目标：
□ Godot 中一只猫（简单几何图形拼贴）
□ 2-3 个基础动作（走到、舔毛、睡觉）
□ 1 个条件积木 + 1 个定时积木
□ 猫能自主执行，玩家能观察
□ 感受"编程→观察→修改→再观察"的循环是否有趣

Demo v0.2 目标：
□ 性格参数影响行为（同一套规则，两只不同性格的猫表现不同）
□ 1 个"意外中断"机制（猫正在执行编程行为时被本能打断）
□ 录屏分享 → 观察"这个 bug 有趣吗？"

Demo v0.3 目标：

## 六、未决问题

1. **编程界面的形式**：节点图（while True: learn() 式）vs 列表式（if-this-then-that 式）vs 时间线式（视频编辑式）？你倾向哪种？Demo 试出来最直观。

2. **单猫还是多猫**：v3 假设单猫深挖。但多猫的"社交互动"（两只猫的行为规则互相影响）是独特的涌现源。1.0 先单猫？

3. **分享机制**：GIF 导出 + 贴纸 + 文字是确定的。要不要"分享行为积木配置"——玩家分享的不是猫的外观，而是"我编的一段行为节目"？

4. **名称**：你提了"哈！基米之家"。确定这个？还是"哈基米之家"（无感叹号和空格）？

5. **Demo 什么时候开始做？** 行为编程→观察的循环需要实际感受才能验证。要不要先定一个最小的积木集（5 个动作 + 2 个控制 + 2 个条件）然后直接开干？

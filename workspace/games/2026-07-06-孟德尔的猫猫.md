## 二、Cat Coat Genetics 完整覆盖

### 2.1 基因座选择

基于真实猫毛色遗传学，选取核心基因座：

| 基因座 | 基因/蛋白 | 染色体 | 遗传模式 | 性状 | 教学点 |
|--------|----------|:--:|---------|------|--------|
| **O (Orange)** | *ARHGAP36* | X | 共显性 | 橘色/黑色/玳瑁 | 伴性遗传、X 失活 |
| **B (Brown)** | *TYRP1* | 常 | 复等位, B>b>b¹ | 黑/巧克力/肉桂 | 复等位基因 |
| **D (Dilute)** | *MLPH* | 常 | 隐性 | 色素稀释（黑→蓝/橘→奶油） | 隐性上位 |
| **W (White)** | *KIT* | 常 | 显性 | 全白（遮盖一切） | 上位性 |
| **S (Spotting)** | *KIT* | 常 | 不完全显性 | 白斑（0%~90%） | 可变表现度 |
| **A (Agouti)** | *ASIP* | 常 | 隐性 | 虎斑底色/纯色 | 经典显隐性 |
| **T (Tabby)** | *Taqpep* | 常 | Mc>b (鲭鱼>经典) | 条纹形状 | 复等位基因 |
| **C (Colorpoint)** | *TYR* | 常 | 多等位, C>cb>cs>c | 重点色（暹罗/缅甸/白化） | 温度敏感型酶 |
| **L (Length)** | *FGF5* | 常 | 隐性 | 短毛/长毛 | 入门教学 |
| **F (Fold)** | *TRPV4* | 常 | 显性+纯合致死 | 折耳（Ff=折, FF=软骨病） | 致死等位基因+伦理 |

### 2.2 为什么加 C 基因座

没有 C 基因座就无法生成暹罗猫、布偶猫、缅甸猫。

```
C (完全显性) > cb (缅甸, 轻度重点色) > cs (暹罗, 重度重点色) > c (白化)

cs/cs = 暹罗式重点色：身体热区浅色、耳/脸/尾/爪冷端深色
cb/cb = 缅甸式：全身略深，重点色对比度低
c/c = 白化（红眼，完全无色素）
```

温度敏感机制：TYR 酶在正常体温（~38.5°C）下活性低 → 身体产色素少 → 浅色。在耳/尾等较冷的末端酶活性恢复 → 深色。**这是猫遗传学中最直观的「基因×环境交互」案例。**

### 2.3 品种特有性状（非毛色）

| 性状 | 基因 | 遗传 | 视觉效果 |
|------|------|:--:|------|
| 折耳 | F (TRPV4) | 显性, 纯合致死 | 耳朵前折 |
| 卷耳 | Cu (未知) | 显性 | 耳朵向后卷 |
| 无尾 | M (Manx) | 显性, 纯合致死 | 无尾/短尾 |
| 卷毛 | re (Cornish Rex) / se (Selkirk) | 隐性 | 卷曲毛发 |
| 短腿 | Mk (Munchkin) | 显性, 纯合致死 | 腊肠猫 |
| 多趾 | Pd (Polydactyly) | 显性 | 6+ 脚趾 |
| 异色瞳 | 白斑+随机发育 | 非遗传 | 一眼蓝一眼铜 |

## 三、表现型空间推算

### 3.1 纯毛色×花纹空间

| 层级 | 维度 | 可见变体数 | 累积 |
|------|------|:--:|:--:|
| 1 | 基础色 (O×B×D) | ~15 | 15 |
| 2 | 虎斑纹 (A+T) | ×4 | 60 |
| 3 | 白斑 (S) | ×5 | 300 |
| 4 | 全白 (W) | +1 | 301 |
| 5 | 重点色 (C) | ×3 | ~900 |
| 6 | 毛长 (L) | ×2 | ~1,800 |

仅毛色维度的可见表现型 ≈ **1,800 种**

### 3.2 加入形态性状

| 7 | 眼色 | ×6 | ~10,800 |
| 8 | 耳型 | ×4 | ~43,000 |
| 9 | 尾型 | ×5 | ~215,000 |
| 10 | 体型 | ×4 | ~860,000 |
| 11 | 卷毛 | ×2 | ~1,700,000 |

**约 100-200 万种视觉可区分的猫外观。** 远超任何玩家的收集能力。

### 3.3 额外的随机化维度（v2 新增）

除了遗传决定的外观，加入**非遗传的随机化**增加每只猫的独特性：

| 维度 | 机制 | 说明 |
|------|------|------|
| **杂色猫的图灵扩散斑图** | 随机种子 → 斑块形状和分布 | 两只基因型相同的玳瑁猫，斑块分布完全不同 |
| **异色部位** | 随机 | 白斑边界处偶尔出现异色的小块（如白猫头顶一小撮黑毛——"命中注定的刘海"） |
| **脸纹不对称** | 随机 | 虎斑纹的左右对称度（0-100%） |
| **体型微小差异** | 多基因+环境 | 同一窝小猫的胖瘦、大小 |
| **性格（行为倾向）** | 隐性多基因 | 胆小/好奇/黏人/独立 — 影响猫在场景中的 idle 动画选择 |

这些维度的存在意味着：**两只基因型完全相同的猫，看起来也可能是不同的个体。** 这从根本上区别于「基因型=外观的唯一决定因素」，更接近真实世界。

```
猫猫来源
├─ 🎁 系统赠送

│
├─ 🛒 购买
│   └─ 猫舍/宠物店（花金币）→ 品种猫的主要来源
│
├─ 🌳 户外抓捕 ⭐（v2 核心理念）
│   ├─ 在「户外场景」中出现流浪猫
│   ├─ 玩家放置诱捕笼/食物 → 等待 → 猫进笼
│   ├─ "抓捕代替购买" — 价值倡导
│   └─ 户外猫的基因型随机、不可预测 → 惊喜源
│
└─ 🧬 自家育种
    ├─ 选择两只已有的猫配对
    ├─ 等待/快进 → 小猫出生
    └─ 定向控制基因型的唯一途径
```

### 4.2 户外场景设计

一个独立于猫舍的「户外」视角——类似猫咪后院的庭院场景：

```
┌──────────────────────────────────────────┐
│  户外场景 — 社区花园/公园/街道角落          │
│                                          │
│  🌳 树    🏚 废弃小屋    🪴 草丛           │
│                                          │
│  🐱 橘猫（流浪）  🐱 黑猫（流浪）           │
│  🐱 三花（流浪）                          │
│                                          │
│  玩家可操作：                             │
│  · 放置食物 🥫 — 吸引更多猫                │
│  · 放置诱捕笼 🪤 — 抓捕特定猫               │
│  · 拍照 📸                                │
│  · 观察猫的社交互动                        │
│                                          │
│  自动发生：                               │
│  · 新的流浪猫随机刷新                      │
│  · 流浪猫之间自然配对 → 产生小猫            │
│  · 一段时间后某只猫"消失"（被 TNR/移走）     │
└──────────────────────────────────────────┘
```

**关键设计**：户外场景不是「另一个育种工具」——它是一个**独立的、活的世界**。玩家可以不育种，只观察户外猫的生态。

### 4.3 野生猫群的自主繁衍（增量/放置元素）

户外猫群有自己的「种群动态」：

```
户外猫群的自主演化：

每 N 分钟/小时（现实时间）：
├─ 随机事件：新流浪猫迁入
├─ 随机配对：两只异性流浪猫交配 → 母猫怀孕
├─ 小猫出生（约 3-5 天后）→ 出现在户外场景
├─ 自然死亡/迁出（老猫消失）
└─ TNR 事件：某只频繁出现的猫被其他人/组织抓捕绝育后放回
```

这意味着：**玩家什么都不做，定期打开游戏也能看到新的猫。**

这种「挂机→回来→发现惊喜」的循环是增量/放置游戏的核心乐趣。玩家从「操作者」变为「观察者」和「偶尔的介入者」。

### 4.4 TNR 机制

TNR（Trap-Neuter-Return，抓捕-绝育-放回）是国际上公认的流浪猫管理最佳实践。

```
游戏内的 TNR 设计：

触发条件：
├─ 玩家多次（如 3 次）遇到同一只流浪猫
├─ 或户外场景中猫口超过阈值
└─ 或玩家主动选择"报告 TNR"

TNR 结果：
├─ 该猫被系统带走 → 绝育 → 耳朵剪标（eartip，TNR 标志）→ 放回户外
├─ 绝育后的猫不再参与野生繁衍 → 控制猫口
├─ 绝育猫可能被「异地放生」— 在户外场景中消失
└─ 也可能被「移送动保」— 进入收养流程（玩家可选择收养）

玩家收益：
├─ 解锁 TNR 成就
├─ 获得「动物友善」标识
└─ 解锁知识卡片：「什么是 TNR？为什么剪耳？」
```

**为什么加这个**：这不是说教——它是**世界逻辑的一部分**。玩家在实际救助组织中看到的 TNR 实践，在游戏中被自然地呈现。而且它解决了游戏设计中的一个实际问题：户外猫口如何控制？TNR 就是答案。

## 五、引导与成就系统（v2 扩展）

### 5.1 目标猫引导任务

游戏通过「目标猫」引导玩家探索遗传系统：

```
任务类型：

📋 日常目标（刷新周期：每天）
  · "今天户外来了一只橘猫，去看看？"
  · "你的三花母猫似乎在找伴…"

🏆 成就目标（一次性）
  · "培育/遇到一只暹罗猫" → 解锁暹罗知识卡片
  · "培育/遇到一只三花公猫" → 解锁 XXY 知识卡片（极稀有）
  · "收集 10 种不同虎斑纹" → 解锁虎斑遗传学知识

🎭 品种挑战
  · "培育一只布偶猫"（cs/cs + 长毛 + 高白斑）
  · "培育一只英短蓝猫"（oo B- dd + 圆润体型）
  · "收集所有 4 种折耳猫毛色"

🐱 meme 猫复现
  · "培育一只看起来像 Grumpy Cat 的猫"
  · "培育一只看起来像 Maru 的猫"
  · "培育一只燕尾服猫（像 Felix the Cat）"
```

### 5.2 多种达成路径

同一个目标可以有多种达成方式，适应不同玩家类型：

```
目标：「获得一只三花猫」

路径 A — 等待派（休闲玩家）：
  完全不操作 → 户外场景中随机刷新流浪三花猫 → 用诱捕笼抓捕
  耗时：不可预测（运气），但零操作

路径 B — 定向育种派（策略玩家）：
  已有玳瑁母猫（Oo）× 白斑公猫（Ss）
  → 配种预览确认三花概率 12.5%
  → 多次配对直到产出三花
  耗时：可控（2-4 代）

路径 C — 最优化派（硬核玩家）：
  分析基因型 → 选择最优父母组合（最大化三花概率的基因型）
  → 利用测交确认隐性等位基因携带者
  → 精准配对 → 1 代产出
  耗时：最短（但需要最深遗传学知识）

路径 D — 社交派：
  去社区交易/领养其他玩家的三花猫
```

**关键是**：所有路径都有效。游戏不强制任何玩法。

### 5.3 「最短路径育种」竞赛

社区挑战：给定两只随机流浪猫，**谁能在最少代数内培育出目标猫？**

```
竞赛模式：
  系统生成：流浪猫 A（基因型随机）+ 流浪猫 B（基因型随机）
  目标：培育出「三花长毛蓝眼」猫
  
  玩家提交：
  ├─ 育种代数
  ├─ 每代的配对选择
  └─ 最终猫的基因型验证
  
  排行榜：最少代数 → 展示最优育种路径
```

这类似于 Zachtronics 的优化排行榜——核心玩法是「育种路径规划」，分享的是「最优策略」而非猫的外观。

## 七、美术策略（v2 更新）

### 7.1 关于「证件照」级别

你提到「如果只是几张证件照、不同姿态的图像或许还可以接受」。这是务实的方向。

**最小可行美术方案**：

```
每只猫的「身份证」视图：
┌─────────────────────┐
│  🐱 正面标准照       │  ← 基因型决定外观，图层叠加生成
│                     │
│  咪咪 · ♀ · 2岁     │
│  玳瑁 · 短毛 · 绿眼  │
│  性格：黏人 · 贪吃   │
└─────────────────────┘

额外视图（可选）：
├─ 侧面照 — 展示体型/尾型
├─ 睡觉姿态
└─ 玩耍姿态
```

图层叠加的最小素材量：
- 1 张基础猫身轮廓（正面）
- 毛色底色层（按 B+D 调色）
- O 基因斑块叠加（母猫玳瑁/三花用 — 随机种子生成斑图）
- 虎斑纹叠加（A+T 决定纹样）
- 白斑面具（S 决定覆盖区域）
- 重点色叠加（cs/cs 时应用于端部）
- 眼/耳/尾变体精灵替换
- 毛长修饰（L 决定毛发边缘的蓬松度）

**总计约 15-30 张素材 → 程序化叠加 → 足够生成百万级变体的「证件照」。**

猫的各种状态（睡姿、舔毛、推杯子）可以作为**额外的精灵帧**——每个状态 1-3 帧。不需要完整的动画管线。

### 7.2 2D 方案对比

#### 方案 A：手绘图层叠加（当前文档方案）

```
核心思路：手绘基础素材 → 程序化着色/遮罩/叠加 → 海量变体

素材清单（~20-30 张）：
├─ 基础层：猫身体轮廓（正面）×1
├─ 毛色掩膜：按基因座分区（身体/耳/尾/脸）→ 着色
├─ O 基因斑块：母猫玳瑁/三花斑块的程序化 mask（随机种子生成斑图边界）
├─ 虎斑纹：鲭鱼纹 / 经典纹 / 斑点纹 / 细纹（Tick） 各 1 张灰度叠加层
├─ 白斑 mask：5 级（0% / 25% / 50% / 75% / 90%）→ 用 shader 做平滑过渡
├─ 重点色灰度 mask：端部叠加（耳/脸/尾/爪），cs 强 / cb 弱
├─ 毛长修饰：短毛→长毛的边缘蓬松度（shader 或 2 种轮廓）
├─ 眼睛精灵：~6 种颜色 × 2 种形状（圆/杏仁）
├─ 耳朵精灵：正常 / 折耳 (Ff) / 卷耳 (Cu) 各 1 张
├─ 尾巴精灵：正常 / 短尾 / 无尾 各 1 张
└─ 体型缩放：粗壮/标准/纤细（transform scale）
```

**优点：**
- 手绘风格可以做出温暖、有辨识度的美术
- 静态证件照质量可控，一张画好就行
- 适合"猫猫身份证"+"图鉴"的核心展示需求
- 素材量小，一个美术 + 一个 TA 可完成

**缺点：**
- 动画是瓶颈：每种姿态需要单独画帧（睡姿、舔毛、推杯子…就是多套图）
- 姿势切换只能做"替换精灵"而非连续过渡
- 视角受限：正面和侧面需要两套素材（或只做正面）
- 动作的多样性和流畅度受限于素材量

**适用场景：** 核心展示 = 证件照 + 静态图鉴，idle 只有 3-5 种切换

---

#### 方案 B：像素艺术 + 调色板替换

```
核心思路：像素风猫精灵 → 调色板索引替换 → 无限变体

类似 Pixel Cats End 的做法：
├─ 猫的像素精灵（32×32 ~ 64×64）
├─ 每个像素存储的不是颜色值，而是「身体区域索引」
├─ 调色板根据基因型动态生成：
│   ├─ 区域 1（基础毛色）：橘/黑/巧克力/肉桂 × 稀释 = 对应颜色
│   ├─ 区域 2（O 基因斑块）：母猫替换区域 1 的部分像素
│   ├─ 区域 3（虎斑纹）：深色条纹色
│   ├─ 区域 4（白斑）：白色
│   └─ 区域 5（端部）：重点色
└─ 动画：像素精灵表（walk/idle/sleep），多帧 → 复用调色板
```

**优点：**
- 素材制作**非常便宜**：一套像素动画 ≈ 几小时
- 调色板替换是零成本的（CPU 端直接 swap）
- 动画成本低：像素画帧比手绘插画帧快 5-10 倍
- 天然适合做很多动画状态（zoomies、推杯子、钻箱子）
- 风格化强，规避"写实猫的恐怖谷"
- 已有成功案例（Pixel Cats End）
- Godot 对 pixel art 支持完善（viewport scaling、nearest filter）

**缺点：**
- 视觉冲击力弱于手绘插画
- 细节表达能力受限（毛长差异在 32px 几乎不可见）
- 情感连接可能不如高清猫图（玩家更不容易"爱上"特定猫）
- 某些基因座性状在像素分辨率下难以区分（如眼色、虎斑纹细节）

**适用场景：** 猫数量多、动画状态丰富、重视玩法胜于视觉

---

#### 方案 C：2D 骨骼动画（Spine / Godot Skeleton2D）

```
核心思路：猫身体拆分部件 → 骨骼绑定 → 程序化换肤 + 骨骼动画

部件拆分：
├─ 身体（躯干 + 四肢 + 头 + 尾）
├─ 每个部件有基础形状，绑定到骨骼
├─ 换肤 = 替换部件的纹理（材质）
├─ 耳朵/尾巴的形态变化 = 替换部件 mesh/sprite
└─ 动画 = 骨骼关键帧（idle/睡/舔毛/行走）

实现路径：
├─ Spine Pro → Godot 运行时（最成熟，需付费）
├─ Godot 原生 Skeleton2D + Polygon2D（免费，工作量大）
└─ DragonBones → 已停止维护，不推荐
```

**优点：**
- **动画多样性最高**：一套骨骼可以驱动几十种动画，不需要逐帧画
- 动画过渡平滑（idle → 睡姿是连续的）
- 部件替换 = 换肤 + 换形态（折耳/卷耳直接换耳朵 sprite）
- 可以做到"猫的不同部位独立动"（耳朵动 + 尾巴摇可以叠加）
- 素材量合理：每个部件 1 张图 + 多种变体

**缺点：**
- **初始成本最高**：需要做好骨骼绑定 + 蒙皮 + 权重，这不是画一张图的事
- Spine 付费（Pro 约 $300/人），且学习曲线陡峭
- 部件拆分后，拼接处的"整体感"需要精心处理（毛色过渡、接缝）
- Godot 原生的 2D 骨骼系统比 Spine 弱，可能需要写额外工具链
- 风格限制：骨骼动画更适合"卡通/剪影"风格，写实风格会暴露拉伸瑕疵

**适用场景：** 动画驱动型的猫猫观赏体验（猫在空间中走动、互动），Spine 值得投资

---

#### 方案 D：像素 3D (Billboard) — 像素精灵在 3D 场景中

```
核心思路：3D 场景（猫舍/户外） + 2D 像素猫精灵（billboard/八方向）

类似：星露谷物语、Core Keeper 的做法
├─ 世界是 3D（或伪 3D）的 — 猫舍有深度，家具可以旋转
├─ 猫是 2D billboard — 始终面朝相机（或八方向精灵切换）
├─ 猫的变体 = 方案 B 的像素调色板
└─ 猫的动画 = 八方向 × N 种状态

八方向精灵 = 正面 / 正侧 / 背面 / 斜向 × 4 = 代价不小
可降级为 4 方向甚至 2 方向（左右翻转）
```

**优点：**
- 猫舍/户外的**场景感**最强（3D 空间 + 2D 角色）
- 场景布置（家具、植物）用 3D 资产比纯 2D 便宜
- 相机可以旋转/缩放，拍照的"取景"维度丰富
- 保留了像素猫的制作便宜 + 调色板灵活

**缺点：**
- 猫的朝向×动作×变体，资产量是纯 2D 的 N 倍
- 八方向像素动画的制作量 = 方案 B × 8
- 技术栈复杂：需要同时管 3D 场景和 2D 精灵
- Godot 的 billboard 实现需要一定 TA 工作

**适用场景：** 场景布置/空间感是核心体验，猫本身不需要 3D 建模

---

#### 方案 E：AI 辅助生成 → 不推荐作为主要管线

```
思路：用 AI 生图（SD/ComfyUI）→ 根据基因型参数生成猫的图片

问题：
├─ 一致性：同一只猫在不同状态/角度下需要保持一致，AI 做不到
├─ 遗传学准确性：AI 不理解"O 基因在 X 染色体上"，玳瑁的斑块分布不可控
├─ 风格一致性：100 万只猫需要同一个画风 → 需要大量 prompt engineering
├─ 版权风险：训练数据来源问题，上架 Steam 有风险
└─ 集成复杂度：实时生成需要 GPU 服务，本地跑慢

可能用途（有限）：
└─ 概念设计 / 风格探索阶段 — 用来快速看"某个基因组合大概长什么样"
```

### 7.4 个人倾向

**如果只做"证件照+图鉴"（最简 v1）：**
→ **方案 A（图层叠加）** 是务实最优解。2 周内可见可玩的猫。

**如果想让猫 "活起来"（有动画行为）：**
→ **方案 B（像素艺术）** 是性价比最高的动画路径。像素画的逐帧动画成本远低于手绘插画，且调色板替换天然契合遗传学需求。

**如果"观赏猫的空间感"是核心体验：**
→ **方案 D（Billboard）** 在场景深度和制作成本之间取得平衡。猫是 2D 像素，世界是 3D 低成本模型，猫舍布置和拍照都更有"空间"感。

**如果有预算和时间做打磨（6 个月+）：**
→ **方案 C（2D 骨骼动画）** 提供了最佳视觉×动画体验。Spine 投资约 $300 + 2-3 周学习曲线，但长期收益巨大。

**不建议一开始就选方案 C**。先做方案 A 或 B 验证核心循环，确认"这个游戏好玩"之后再决定是否升级美术。

### 7.5 竞品分析：已有的 3D 猫游戏

在讨论方案之前，先看两个已存在的 3D 猫游戏，它们分别代表了 low-poly 和写实两条路。

#### 竞品 1：Pat the Cat — Low-Poly 桌宠 + 挂机

```
Unity 制作 | Steam 有售 | 类型：桌面宠物 + 放置

核心特征：
├─ Low-poly 3D 猫模型，风格可爱
├─ 默认几组皮肤可用（预设配色，非自定义）
├─ 猫有叫声（情绪表达）
├─ 时间积分兑换个性化：瞳孔颜色、家具等
├─ 核心循环：桌面宠物 + 挂机
├─ 常见猫猫交互都有（摸头、逗猫等）
└─ ❌ 没有配种/遗传系统
```

**关键观察：**
- Pat the Cat 证明了 **low-poly 3D 猫 + 桌宠挂机** 这个品类有市场
- 它的换肤是**预设皮肤**（几组固定配色），不是程序化生成 → **这是我们的差异化空间**
- 没有自定义皮肤功能 → 如果我们的猫由遗传学驱动，每只猫的外观都是独一无二的，"皮肤"的数量级完全不同
- 没有育种系统 → **这是我们最核心的差异化**
- 它的交互丰富度（摸猫、叫声、家具）是作为桌宠的基线——我们要超越这个基线，至少在交互种类上不能比它少

**可借鉴的：**
- 时间积分兑换个性化和家具 → 对应我们的"户外场景布置"和"猫玩具解锁"
- 猫叫声系统 → 不同性格的猫可以有不同的叫声频率和类型
- 桌面宠物模式 → 可以作为"最小化窗口"模式，猫在屏幕角落活动

---

#### 竞品 2：猫咪漂移 Cat Drift — 写实 3D 养成 + 竞速

```
UE 制作 | Steam 有售 | 类型：养成 + 竞速

核心特征：
├─ 基于 UE，现实拟真画风
├─ 可以看见猫的绒毛（high-fidelity fur shader）
├─ 猫的运动经过精心调整，非常拟真
├─ 有猫猫第一人称视角
├─ 简介提到可以"培育猫猫"
└─ ⚠️ 没有 demo 试玩，育种深度未知
```

**关键观察：**
- 写实 3D 猫的门槛非常高：UE 的 fur shader + 拟真动画 + 第一人称 → 这不是个人开发者能做的
- **"培育猫猫"可能只是简单的配对**（选 A+选 B → 随机外观小猫），不一定是基因级别的遗传模拟
- 如果它做了基因级育种但藏得很深，那它是直接竞品；如果只是皮肤混搭，那我们有机会
- 竞速是它的核心差异化 → 我们的差异化是**遗传学深度 × 户外生态 × TNR**

**值得关注但不必模仿的：**
- 猫的绒毛和拟真动画：是好，但成本太高
- 第一人称猫视角：有趣但不必要（我们的游戏不是"扮演猫"而是"观察猫"）
- 竞速系统：与我们的方向无关

**需要调查的：**
- 它的"培育"系统到底做多深？是纯外观混搭还是基因模拟？
- 玩家社区对育种深度的反馈

### 7.6 3D 方案分析

#### 方案 F：3D 绑骨模型 + 程序化材质/换皮（"写实 3D"路线）

```
3D 猫模型管线：
├─ 基础猫模型：一体成型，骨骼绑定完整（四足动物 skeleton）
├─ UV 展开：身体各区域映射到纹理坐标
├─ 换肤方式：
│   ├─ 纹理贴图替换：不同毛色/花纹 = 不同的 albedo texture
│   ├─ 程序化材质（shader graph）：基因型参数 → shader 实时生成
│   └─ 混合：基础色 + detail map（虎斑） + mask（白斑/重点色）
└─ 形态变体（耳朵/尾巴）：骨骼 scale/旋转 或 mesh swap
```

**优点：**
- **表现力最强**：光影、毛皮材质、环境反射 → 真实感或风格化都可以
- **动画管线成熟**：Mixamo / Unity Asset Store / UE Marketplace 有四足动物动画包
- 旋转/缩放/观察猫的任意角度 → "观赏猫"体验最佳
- 3D 场景的猫舍/户外天然有空间深度
- 与「哈！基米之家」3D 行为编程方向一致（资产可复用）

**缺点：**
- **初始成本非常高**：
  - 猫的 3D 建模 + 骨骼绑定 + 蒙皮 = 1-2 周（经验丰富的 3D 美术）
  - 纹理/材质系统 = 1-2 周（TA）
  - 动画（idle/走/跑/睡/舔/跳）= 大量工作，一套四足动画包约 $50-200
- 性能开销：场景中有 N 只猫时，GPU 压力
- 需要 3D 美术或外包预算
- 如果风格写实 → 恐怖谷风险（"为什么这只猫的眼睛像塑料？"）

**适用场景：** 预算充足、团队有 3D 美术、目标是 PC/主机品质的游戏

---

#### 方案 G：Low-Poly / Voxel 风格

你说的 "类 MC low-poly" 大概指这种：

```
Blockbench 风格的猫模型：
├─ 猫身体 = 几个立方体/低多边形拼接（头 → 长方体，身体 → 长方体，腿 → 4 个长方体）
├─ 耳朵/尾巴同理 → 几何体
├─ 纹理 = 极简 pixel art texture（16×16 ~ 32×32 的 UV 贴图）
├─ 换肤 = 替换贴图（比写实模型的贴图制作便宜 10 倍）
└─ 动画 = 骨骼绑定在 Blockbench 中完成，导出到 Godot/Unity
```

**具体实现路径：**
- **Blockbench**（免费）→ 建模 + 贴图 + 骨骼 + 动画 → 导出 glTF → Godot 直接使用
- 流程：建模猫 → 画 16×16 贴图 → 绑骨骼 → 做动画 → 在 Godot 中用代码换贴图

**优点：**
- **建模成本极低**：一只 low-poly 猫 ≈ 2-4 小时（vs 写实猫 1-2 周）
- **贴图成本极低**：16×16 或 32×32 的像素贴图，改颜色/花纹 = 改几个像素
- 换肤非常简单：直接 swap material/texture，甚至可以运行时 pixel-by-pixel 生成贴图
- 动画制作快：Blockbench 自带动画编辑器，简单的 idle/走/睡动画 ≈ 几小时
- 风格化安全：low-poly 天然回避恐怖谷，可爱是确定的
- 性能极好：一只猫 ≈ 几十个三角面，场景放 50 只无压力
- Godot 兼容性好：glTF 导入支持完善
- **已有先例**：大量独立游戏使用这种风格上架 Steam（如 Garden Paws、Ooblets、Mineko's Night Market）

**缺点：**
- 风格接受度：low-poly 不是所有人的菜，有些人会觉得"太粗糙"
- 细节表现力弱：毛长差异、虎斑纹细节在 16×16 贴图上的表现力有限（但足够区分）
- 与"温暖治愈"的定位需要统一：low-poly 可以温暖（参考 A Short Hike），但需要美术方向明确
- 动画流畅度取决于动画师水平，不是风格本身的问题

**适用场景：** 小团队/个人开发者、追求快速出原型、每只猫都是一个独立 3D 个体在场景中活动

---

#### 方案 H：体素（Voxel）风格

```
Magicavoxel 风格的猫：
├─ 猫由体素堆叠（类似 Teardown / 3D Dot Game Heroes）
├─ 每个体素 = 一个颜色
├─ 换肤 = 替换体素柱的颜色值 → 像素级控制
└─ 动画 = 骨骼绑定体素 mesh（或做 voxel 帧动画）
```

**优点：**
- 换肤极简单：每个体素直接赋值颜色
- 风格独特，辨识度高
- 建模直观（像搭积木）
- 没有 UV 贴图的概念，改色就是改 voxel 数据

**缺点：**
- 动画是硬伤：体素 mesh 绑骨骼后拉伸会破坏"方块感"
- 风格过于特殊，受众窄
- 对"猫猫观赏"来说，体素的温暖感不如像素 hand-drawn
- Godot 对体素支持一般（需要插件或自定义导入）

**适用场景：** 偏小众，除非本身就喜欢体素风格，**不太推荐**

### 7.8 最推荐的路径

#### 🥇 首选：Low-Poly 3D（方案 G）

**理由：**

1. **刚好踩中你的需求**：你提到了 3D 绑骨 + 换肤和 low-poly 两种 3D 方案，而 low-poly 恰好是两者中**制作成本最低**的，同时保留了 3D 的全部优势（空间感、多角度观察、动画管线）。

2. **已验证的市场**：Pat the Cat 证明了 low-poly 3D 猫 + 桌宠挂机模式在 Steam 上可行。但它的换肤是**预设皮肤**，没有自定义、没有遗传系统 → **我们在此基础上叠加 Cat Coat Genetics，外观由基因型驱动而非预设，这是核心差异化**。

3. **猫的基因多样性 → 贴图极简**：low-poly 猫的 UV 贴图只有 16×16 或 32×32 像素。运行时生成贴图（根据基因型参数写像素颜色）是**完全可行的**——不需要任何预渲染素材。这意味着 100 万种变体的美术成本 = **0 张预渲染图片**。

4. **动画复用**：所有猫共享同一套骨骼和动画（idle/sleep/lick/zoomies/walk），换贴图不影响动画。做 10 个动画状态 = 10 套动画 × 1 个骨架 = 所有猫通用。Pat the Cat 能做到的猫猫交互，我们在技术上是同级别的。

5. **Blockbench 全链路免费**：建模、贴图、骨骼、动画全在一个工具完成，导出 glTF 到 Godot。学习成本 ~1 周。

6. **与你已有的「哈！基米之家」方向一致**：如果哈基米之家走 3D 行为编程，猫的模型/动画资产可以跨项目复用。

**成本估算：**
```
一只 low-poly 猫的完整资产链：
├─ 建模 + UV + 基础贴图：4-6 小时
├─ 骨骼绑定 + 蒙皮：2-3 小时
├─ 核心动画（idle/sleep/walk/lick/sit/jump）：8-12 小时
├─ 贴图生成系统（基因型参数 → 运行时生成贴图）：1-2 天（程序员）
└─ 形态变体 mesh 替换（折耳/卷耳/短尾等）：2-3 小时/个

总计：达成"一只活着的、可换肤的、有基本动画的低模猫"≈ 2-3 周
```

**与 Pat the Cat 的差异化空间：**
| 维度 | Pat the Cat | 孟德尔的猫猫（计划） |
|------|:--:|:--:|
| 猫外观来源 | 预设皮肤（几组） | 基因型驱动（百万级变体） |
| 获得新猫 | ? | 户外抓捕 / 育种 / 交易 |
| 遗传/育种 | 无 | 核心系统（10 基因座 Cat Coat Genetics） |
| 户外生态 | 无 | 流浪猫种群动态 + TNR |
| 教育 | 无 | 遗传学知识卡片系统 |
| 社区 | ? | 基因型分享码 + 育种竞赛 |

#### 🥈 次选：2D 图层叠加（方案 A）

如果目前没有 3D 美术能力，**方案 A 仍然是最好的第 0 步**：
- 2 周做出可看的猫 → 验证遗传学引擎和玩法循环
- 确认核心好玩后，再决定是否投入 3D

#### 🥉 备选：2D 像素（方案 B）

如果完全不想碰 3D，且想让猫"活起来"（有很多动画），像素是 2D 中最经济的动画方案。

### 7.9 关于 Low-Poly 的贴图运行时生成（技术补充）

这是 low-poly 方案最核心的技术优势。简述实现：

```
基因型 → 贴图生成的流程：

1. 猫的 UV 展开按身体区域分区：
   ┌────────────────────┐
   │  耳朵L  │  耳朵R    │  ← UV 岛 1：耳
   │   脸（眼/鼻/口）    │  ← UV 岛 2：面部
   │   身体（背/腹）     │  ← UV 岛 3：躯干
   │   腿 ×4            │  ← UV 岛 4：四肢
   │   尾               │  ← UV 岛 5：尾巴
   └────────────────────┘

2. 对于 32×32 的贴图，每个 UV 岛对应一段像素区域

3. 基因型解读：
   O 基因 → 基础色是橘还是黑（玳瑁母猫 → 随机斑块 mask）
   B 基因 → 黑色/巧克力色/肉桂色（eumelanin 色调）
   D 基因 → 是否稀释（dd → 黑变蓝灰、橘变奶油）
   A 基因 → 有无虎斑底（aa → 纯色，A- → 虎斑底）
   T 基因 → 虎斑纹样（鲭鱼 vs 经典）
   S 基因 → 白斑覆盖比例
   W 基因 → 全白（覆盖所有）
   C 基因 → 重点色（端部加深）
   L 基因 → 毛长（可以在贴图上做边缘羽化，但主要靠 shader）

4. 运行时贴图生成伪代码：
   texture = new ImageTexture(32, 32)
   for each pixel in 32×32:
       region = uv_to_region(pixel.uv)
       base_color = region_base_color(region, genetics.O, genetics.B, genetics.D)
       if genetics.W_ == "WW" or genetics.W_ == "Ww":
           color = WHITE
       elif is_white_spot(region, pixel, genetics.S):
           color = WHITE
       else:
           color = base_color
           if genetics.A_ != "aa":
               color = apply_tabby(color, region, pixel, genetics.T)
           if has_point(genetics.C):
               color = apply_colorpoint(color, region, genetics.C)
       texture.set_pixel(pixel.x, pixel.y, color)

5. 这 50 行代码 = 100 万种猫的贴图全部自动生成
   不需要任何额外的手绘素材
```

这意味着：**只需要画 1 张参考贴图（示范猫），贴图生成系统就能覆盖所有变体。**

## 九、核心玩法循环（待讨论 ⚠️）

v2 暴露了一个核心问题：**这个游戏里玩家大部分时间在做什么？**

几个混合共存的可能性：

### 9.1 观察为主（猫咪后院模型）

```
打开游戏 → 看看户外有什么新猫 → 喂食 → 拍照 → 关闭
偶尔 → 发现一窝新小猫（野生繁衍的结果）→ 惊喜
偶尔 → 用诱捕笼抓一只感兴趣的猫 → 收入猫舍
偶尔 → 配对一次 → 等待 → 看小猫
```

节奏：每天 3-5 分钟。类似猫咪后院（Neko Atsume）的「来访-离开」节奏。

**优点**：零压力，适合猫爱好者。**缺点**：深度浅，对核心玩家粘性不足。

### 9.2 育种规划为主

```
设定目标 → 分析基因型 → 配种预览 → 配对 → 等待 → 观察子代
    ↓
不满意？→ 调整配对 → 再试
满意！→ 解锁图鉴 → 设定下一个目标
```

节奏：每次 10-30 分钟的专注育种 session。

**优点**：有策略深度。**缺点**：和「猫猫空间」的休闲氛围拉扯。

### 9.3 混合模型

两种节奏共存——玩家自己决定今天是想「看看猫」还是「认真育种」：

```
登录 →
├─ 休闲模式：逛户外 → 拍照 → 喂猫 → 5 分钟关闭
└─ 育种模式：打开育种面板 → 规划配对 → 执行 → 30 分钟沉浸
```

户外猫群的自主繁衍在后台持续运行（增量层），玩家任何时候回来都有新东西看。育种是玩家**主动加速**这个自然过程的手段。

## 十、未决问题

### 核心方向（最优先）

1. **这个游戏的「1 分钟循环」是什么？** 玩家打开游戏后的第一个 60 秒在做什么？看到什么？点击什么？

2. **玩家和猫的关系是什么？**
   - 收藏家（猫是收集品）
   - 饲养员（猫是需要照顾的生命）
   - 观察者（猫是独立于玩家的自主存在）
   - 策展人（猫是展示品，空间是画廊）

3. **户外场景和猫舍的关系**：两个独立空间？还是户外→抓捕→猫舍的单向流动？猫舍的猫能放回户外吗？

### 体量与节奏

4. **游戏的「心跳」是多长？**
   - 猫咪后院式：每天 3 次 × 3 分钟
   - 放置游戏式：挂机 2h → 回来收 10 分钟
   - 主动游戏式：一次玩 30-60 分钟

5. **核心图鉴需要多少条目？** 50 个（2h 可完成）还是 200 个（需要数周）？

### 美术可行性

6. **「证件照」级别够不够产生情感连接？** 如果你只能做 1 张正面静态图（图层叠加），玩家会「爱上一只猫」吗？还是需要至少 3-5 种不同姿态？

7. **猫的状态动画的制作量**：以 Godot 为例，2D 骨骼动画（Spine/Anima）vs 帧动画 vs 纯静态+特效（眨眼、耳朵动）——哪个是合理的目标？

### 系统设计

8. **户外猫群的「种群动态模拟」做多深？**
   - 最简：定时随机刷新+随机消失
   - 中等：有简单的数量模型（食物量→猫口容量，季节性波动）
   - 深：每只猫有年龄、健康、社交关系（两只猫可能形成「伴侣」关系）

9. **要不要猫的「死亡」？** 老猫自然老去？还是永远活着？这决定了游戏的氛围是「温暖永恒」还是「真实的生命循环」。

10. **「最短路径育种」竞赛是核心功能还是锦上添花？** 如果做，需要配种模拟器可以「撤销」和「试算」——这是额外的 UI 复杂度。

### 与「哈！基米之家」的关系

11. **开发顺序？** 这个更小更独立 → 先做作为热身？还是两个并行？资源共享程度（遗传学引擎）决定了开发效率。

12. **两个游戏的猫数据互通吗？** 在「孟德尔的猫猫」中收集的猫，未来能否导入「哈！基米之家」进行行为编程？如果是，需要从 v1 就设计数据格式。

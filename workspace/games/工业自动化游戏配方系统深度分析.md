## 一、配方系统分类框架

工业自动化游戏中不存在单一的"配方"定义。同样是"用A生产B"，15款游戏在架构层面做出了根本不同的选择。我们首先建立一个四类分类体系。

### 1.1 物料配方型 (Material Recipe)

这是该类型的主流范式：配方 = 明确的输入物品列表 + 输出物品列表 + 加工时间 + 所需的制作建筑。

```
配方 = ⟨Inputs, Outputs, Time, Category, Machine⟩
Inputs = {Item₁ × n₁, Item₂ × n₂, ..., Fluid₁ × n₃, ...}
Outputs = {Itemₐ × mₐ, ...}
```

**核心假设**：输入被**消耗**，输出是新物品，配方是一个"黑箱变换"。玩家不关心变换内部的物理过程——为什么3块铁板+2个齿轮能造出发动机，纯粹是设计师设定的数值。

该范式下各游戏的差异化选择：

| 维度 | Factorio | DSP | Satisfactory | CoI | Mindustry | Riftbreaker |
|------|----------|-----|-------------|-----|-----------|-------------|
| **配方-建筑绑定** | 松（组装机可造任何组装配方） | 中（按类别绑定：冶炼/组装/化工） | 中（按端口数+流体能力绑定） | 紧（每建筑类型固定配方集） | 极紧（一建筑一配方） | 紧（建筑类型固定产出） |
| **多输出配方** | 约8个（石油、铀、Space Age废料回收） | 约6个（精炼、裂解、对撞机） | 几乎无（仅核废料例外） | **普遍存在**（大多数配方2-4输出） | 2个（电解器+概率分离器） | 无 |
| **流体处理** | 完整管道系统（压力、温度、吞吐量） | 简化（流体=传送带上的物品） | 完整管道系统（无压力模拟，有扬程） | 完整管道系统（单产品管道） | 管道+传送带分离 | 全局库存，无物流 |
| **配方发现方式** | 科技树直接解锁 | 科技树+稀有矿脉发现 | 科技树+硬盘驱动器探索 | 科技树 | 科技树 | 研究时间门控 |

**关键差异总结**：

- **Factorio**追求"配方作为开放原语"——任何组装机可以造任何组装配方，约束来自机器速度/模块/物流连接，而非硬编码分类。这最大化玩家组合自由。
- **DSP**折中选择——通过建筑类别（冶炼/组装/化工/粒子）约束配方，但类别内部自由。稀有矿脉的"发现即捷径"机制是独特贡献。
- **Satisfactory**通过物理端口数约束配方——建筑有明确1/2/4输入端口限制，流体端口独立。这是三维空间中视觉可读性驱动设计决策的典型例子。
- **CoI（工业巨头）**将多输出作为**默认范式**——单输出是早期手工制作的例外。每条生产链产废，强制执行废物管理。
- **Mindustry**采用"每个工厂一个配方"的极简约束——工厂就是配方的物理化身，没有多用途机器。空间即资源，工厂占地面积直接与产出多样性竞争。

### 1.2 几何变换型 (Geometric Transformation)

该范式下不存在"材料消耗"，取而代之的是**形状的几何操作**。

**Shapez的4操作体系**：

```
操作集 O = {Cut, Rotate, Stack, Paint}
形状空间 S = 所有可达形状的集合
配方 = S* → S（形状序列到目标形状的有序操作序列）
```

Shapez的形状代码（如 `CbCuCbCu:Sr------:--CrSrCr:CwCwCwCw`）**同时是输入规格、输出规格和分解指南**。这与物料配方型的根本差异在于：

- 配方是**派生的**而非给定的——玩家必须从目标形状逆向推导操作序列
- 输入不被消耗——同一组块经过变换成为输出
- 操作具有**代数性质**：Cut是扇出，Stack是扇入，Rotate和Paint是1对1。组合遵循结合律（有条件）和非交换律
- 不存在"配方比例"——吞吐量是唯一指标

**Infinifactory的13个操作块**：

```
操作集 = {Convey, Weld, Eviscerate, Rotate, Push, Sense, ...}
配方 = 三维空间中操作块的物理排列
```

Infinifactory将每个关卡定义为"将输入体素结构变换为目标体素结构的3D装配线"。配方的复杂度来自于操作的**空间拓扑**——焊接时机、切割位置、旋转轴——而非物料数量。三个正交优化维度（周期数/占地面积/块数）意味着同一变换有多个"正确"答案，每个代表不同的设计哲学。

**与传统物料配方的关键差异**：

| 维度 | 物料配方型 | 几何变换型 |
|------|-----------|-----------|
| 输入命运 | 被消耗，转化为输出 | 保持不变，物理形态被修改 |
| 配方来源 | 设计师设定 | 玩家从目标逆推 |
| 中间产物 | 不同类型的新物品 | 同一物理块的不同空间配置 |
| 依赖图 | 树/DAG | 线性操作链 |
| 核心挑战 | 比例配平与物流规模 | 空间推理与操作顺序 |

### 1.3 物理模拟型 (Physics-Driven Transformation)

这是该类型中**最深但最不可移植**的配方范式。ONI的转化系统不能简单归约为"输入→输出"的函数映射，因为**输出状态取决于转化的物理条件**。

**为什么ONI不能归约为配方**：

一个标准的物料配方：
```
电解器（标准配方模型会这样描述）：
  输入：1000g/s 水
  输出：888g/s 氧气 + 112g/s 氢气
  时间：即时（持续过程）
```

但ONI的实际转化是：
```
电解器（实际游戏行为）：
  输入：1000g/s 水（任意温度）
  输出：
    - 888g/s 氧气 @ 最低 70°C（或水温，取更高者）
    - 112g/s 氢气 @ 最低 70°C（或水温，取更高者）
  隐含物理效应：
    - 净热删除：若进水温度<70°C，输出温度固定70°C，
      系统实质上"创造"了热量
    - 净热删除量 = 1000g × 4.179 SHC × (70 - T_water) DTU/s
    - @20°C进水：约 208,950 DTU/s 热删除
    - 此效率约 80%（输入热/输出热）
  副产物：无直接副产物，但氢气若积累→气压过高→电解器停止
```

配方输出不是固定值，而是**输入温度的函数**。这个事实使得ONI的转化具有以下独特属性：

1. **温度是配方的第三维输入**——即使物品类型相同，不同温度的同一物质是完全不同的资源（20°C水 vs 95°C水 vs 蒸汽）
2. **相变是隐式配方**——温度超过相变阈值时，物质自动转化为不同形态（水→蒸汽→水，原油→石油，污染水→蒸汽+泥土），这与任何建造物无关
3. **热容矩阵是隐藏的配方图**——每种物质有独特比热容，决定加热/冷却的成本。这创建了一个隐藏的"热值经济"
4. **配方结果是上下文依赖的**——同一电解器在热环境中输出不同

**物理层作为"元配方"**：

```
转化 = {输入 + 转化条件 + 输出 + 隐含产物 + 环境约束 + 失败模式}
```

其中：
- **隐含产物** = 废热、副产物气体、压力变化（非物品产出）
- **环境约束** = 温度范围、气压范围、周围物质类型
- **失败模式** = 过热损坏、气压过高停止、物质相变破坏管道

此分析框架揭示：物料配方是物理转化的**退化形式**——当环境约束为零、隐含产物可忽略、失败模式不存在时的特殊情况。

### 1.4 空间物流型 (Spatial-Logistic Recipe)

在该范式中，配方**不是建造物的属性，而是物流网络的属性**。

**Railgrade：站台连接即配方**

```
配方 = ⟨输出站, 输入站, 连接铁轨⟩
输出站类型决定产物，输入站类型决定需求
铁轨的拓扑结构（坡度、分支、信号）决定吞吐量
```

Railgrade的约34种资源经过46种工业建筑，但不存在传统的"配方配平"。铜矿站不需要"知道"它连接的是电线工厂还是仓库——原料自动流向有需求的站台。生产链由**铁路图**而非**配方书**定义。配方的优化是空间优化：路径长度、隧道/桥梁选择、信号阻塞最小化。

**Assembly Line 2：空间布局即配方**

```
配方 = 机器类型 + 网格位置 + 朝向
输入/输出由固定端口决定（如制作器从左侧输入，右侧输出）
布局的可行性由2D网格内的空间拟合决定
```

Assembly Line 2约50种资源、21+机器类型，但不存在独立的"配方选择"步骤。玩家不选择"铜线配方"→ 玩家放置一个Starter（产出铜线）并规划其输出的2D路径到下一个机器。**布局就是配方**——两个玩家不可能有"相同"的配方而不同的布局，因为布局定义了数据流。

**与传统物料配方的对比**：

| 维度 | 物料配方 | 空间物流配方 |
|------|---------|-------------|
| 配方定义 | 物品变换函数 | 物流网络拓扑 |
| 玩家操作 | 选择配方+配平比例 | 绘制空间连接 |
| 优化目标 | 比例匹配+规模扩展 | 空间效率+路径最短 |
| 可迁移性 | 比例可跨场景复用 | 布局绑定到特定空间 |

### 2.1 配方规模

|------|:--:|:--:|:--:|------|
| **Factorio 1.1** | ~180-200 | ~35-40 | 9（铁矿石→火箭发射） | DAG + 少量催化循环 |
| **Factorio Space Age** | ~350+ | ~60+ | ~10+（品质升级循环叠加） | DAG + 品质回收循环 + 催化循环 |

| **Plan B: Terraform** | ~20+ | ~10 | 2-3 | 线性链 |

| **Assembly Line 2** | ~50资源/21机器 | ~15 | 6-8（基础→AI核弹轰炸机） | 漏斗（汇聚到2终极产品） |

**关键观察**：

1. **配方数量与游戏时长的相关性不完全是线性的**。Factorio约200配方支撑100+小时原版体验，Pyanodon改版700+配方支撑1000+小时。Satisfactory 216+配方支撑150+小时。深度的边际增量递减——每增加100个配方，体验时长增量递减。

2. **中间产品占比是比配方总数更好的深度指标**。Factorio约20%的配方是"纯中间产品"（只作为输入，不进入世界）。CoI的比例接近35%（大多数物品经过至少一个处理步骤后才成为"终端"）。而Riftbreaker中间产品占比<10%，链条直接从矿石跳到建筑。

3. **链深度与系统复杂度呈超线性关系**。链深3意味着~3个建筑类型和~3条物流连接。链深9意味着~20+建筑类型和指数级增长的物流组合。这是为什么Riftbreaker感觉"简单"而Factorio感觉"深"的配方学解释。

### 2.2 配方图拓扑分析

配方之间的依赖关系可以被建模为图论结构。图的拓扑类型直接决定玩家体验的结构。

#### 类型一：纯树形结构

```
    最终产品
    /   |   \
  中A  中B  中C
  / \   |   / \
原原 原 原 原 原
```

每个最终产品有且仅有一条从原材料到最终产物的路径。**极少出现在该类型中**（Riftbreaker接近此模型，Planet Crafter也是）。优点：无歧义，易于学习。缺点：无决策空间——玩家无法选择"怎么造"，只能选择"造多少"。

#### 类型二：有向无环图（DAG）

这是该类型最常见的拓扑：

```
      最终产品
     /    |    \
   中A   中B   中C
  /  \  /  \  /  \
原1 原2 原3 原4 原5
```

多种中间产品共享共同的前驱，一种原材料进入多条下游链。**因子分解**是核心设计工具——哪些中间产品应该从多个最终产品中"提取"为共享节点？

Factorio的板子（绿色电路进入多种下游链）和Satisfactory的螺丝（最极端的分叉节点——15+下游配方使用螺丝）是典型例子。

#### 类型三：带副产物的DAG

```
      最终产品A
     /    |
   中A   中B ──→ 副产物X
  /  \  /  \        |
原1 原2 原3       最终产品B
                    |
                   中C
```

多输出节点 = 必须处理所有输出否则系统堵塞。这是**从玩家角度最重要的拓扑特征**——它将"选择"转化为"义务"。

Factorio的石油精炼、CoI几乎所有的熔炼配方、ONI的天然气发电机（产出电力+污染水+二氧化碳）都属于此类型。

#### 类型四：带循环的图

```
    → 操作 ←
   /        \
  输入      输出（净正）
   \        /
    ← 回流 ←
```

催化循环的特征：同一物质同时出现在输入和输出侧，净输出为正。

实例：
- Factorio Kovarex浓缩：40 U-235 + 5 U-238 → 41 U-235 + 2 U-238（净+1 U-235）
- Factorio Space Age品质升级循环：制造→回收→再制造→更高品质
- ONI SPOM：电解→氢气燃烧发电→电力驱动电解（净能量正向）
- CoI快中子增殖反应堆：消耗+再生核燃料的闭环

循环为配方图增加了一个新的维度：不再是"从A走到B走多远"，而是"循环一周净收益多少"。设计循环时，关键是**净产率必须为正**——否则循环退化为一端不通的死胡同。

#### 类型五：操作组合树（Shapez）

```
                最终形状 (4层)
               /              \
          层12(2层)          层34(2层)
         /        \         /        \
      层1(红圆)  层2(蓝方) 层3(绿星) 层4(黄风车)
      /  |  \    /  |  \    ...
  切割 上色 旋转 ...
```

这不是物料图，而是**操作图**：每个节点是一个变换操作（切割/上色/旋转/堆叠），边表示形状在操作间的流动。树结构的根是最终形状，叶是源形状（从矿机中提取的完整圆形/方形/星形/风车形）。

**为什么拓扑重要**：

1. **DAG → 线性规划思维**：玩家解体"我需要多少原材料来支持1个/秒的最终产出？"这是一个代数分解问题。
2. **带副产物的DAG → 系统平衡思维**：玩家必须确保所有输出的消费≥生产。这是线性规划+约束满足。
3. **带循环的图 → 稳态均衡分析**：玩家必须找到净产率与下游消费的均衡点。循环的启动条件（Kovarex需要先积累40个U-235）创造了独特的门槛设计。
4. **操作树 → 逆向规划思维**：从目标反推操作序列。这是一个搜索/证明问题，而非代数问题。

### 2.3 比例/配平设计

配方比例是"玩家计算vs设计师计算"的界面。该类型在三个哲学取向上存在重大分歧：

#### 精确比例派（Factorio, Satisfactory）

每个配方的每个数字都被精心设计为精确约束。

**Factorio实例**：电子电路（绿色）3:2比例
```
铜线：2线/0.5s → 4/s（制造速度1）
绿板消耗：3线/0.5s → 6/s
比例：3台铜线机:2台绿板机（3×4=12/s; 2×6=12/s）
```

这是玩家遇到的第一个真正的比例谜题。它教授一个基本原则：**高吞吐量单用途中间产品不应进入物流网络**——直接插入（铜线机→绿板机，无传送带）是最优解。

**Satisfactory实例**：配方设计的60进制基础
```
大多数产出率是60的倍数或分数（60/min, 30/min, 120/min, 15/min）
机器在100%时钟下产生整洁的2:1、3:1、3:2比例
铁板(20/min) → 铁棒(15/min) → 螺丝(60/min) → 强化铁板(5/min)
```

这是**明确故意的设计选择**。在需要玩家在三维空间中手动布线的游戏中，整洁的比例不是品质之便——而是必需品。Factorio的2D网格和蓝图系统可以吸收复杂比例（5:7:11的生产块仅需复制粘贴），因为缩放成本近乎为零。在Satisfactory中，丑陋的比例加三维布线的认知负载将令人难以承受。

**代价**：整洁的比例使配方优化感觉"被解决"——一旦你找到数学最优链，正确答案通常明确单一。Factorio的凌乱比例意味着永远存在更优的配比。

#### 模糊比例派（DSP, Mindustry）

DSP和Mindustry的比例存在但容错空间更大。Mindustry的采矿机产出率依赖矿脉几何（钻头覆盖多少矿块），不同地图产出不同。DSP的矿脉是无限的，速率由矿脉数量而非效率决定——优化关注"每分钟生产多少"而非"钻多少矿"。

#### 无比例派（Shapez, Infinifactory）

吞吐量是唯一指标。没有"3个A+2个B→1个C"的配平——只有"操作A处理500形状/min流向操作B"。优化是完全关于节奏和空间的，而非关于整数比例的。

#### 物理替代派（ONI）

比例被物理约束替代。ONI的电解器严格产出888g/s氧气+112g/s氢气——但关键约束不是"我需要多少电解器来供应N个复制人"，而是"这个建筑产生的热量能否被环境吸收，不然它会过热损坏"。数学从代数转向微分方程（热流率、比热容、导热率）。

**比例设计如何塑造玩家体验**：

| 比例哲学 | 玩家行为 | 结果体验 |
|---------|---------|---------|
| 精确（Factorio） | 外部计算器+蓝图系统中的比例求解 | "我是工程师"满足感 |
| 整洁（Satisfactory） | 心理算术+简单除算 | "一切对齐"审美满足 |
| 模糊（DSP/Mindustry） | 近似估算+"足够好就行" | "我不需要完美"解放感 |
| 无比例（Shapez） | 吞吐量瓶颈分析 | "让我变快"节奏感 |
| 物理替代（ONI） | 热平衡分析+DTU追踪 | "我在驯服物理"掌控感 |

## 三、可组合性分析

可组合性衡量"配方系统支持组合选择与模块化重用的程度"。高可组合性意味着玩家花更多时间在**设计**上，低可组合性意味着玩家花更多时间在**执行**上。

### 3.1 配方替代与多路径

#### Factorio：3层替代路径体系

| 替代层 | 机制 | 实例 | 影响范围 |
|:--:|------|------|------|
| **配方替代** | 同一物品可通过不同配方制造 | 石油→3种固体燃料路径（轻油最优、重油居中、石油气最差）；裂解链（基础/高级石油加工/煤液化） | 局部决策：为该下游消费者选择最优路径 |
| **机器替代** | Space Age专属：同一配方在不同机器中运行，内置产能不同 | 处理单元可在组装机3（0%产能）、EM工厂（50%内置产能）、低温工厂（0%内置+8模块槽）中制造 | 全局重构：为整条生产链选择最优机器类型 |
| **品质替代** | 品质模块使相同输入产出随机更高层级的物品 | 普通组装机→罕见/稀有/史诗/传说组装机。升级循环提供统计性替代路径 | 统计优化：概率×生产成本的最优模块配置 |

**多路径指标**：在Factorio中，任何中间产品平均有~1.5条不同的制造路径（考虑所有替代层）。处理单元（蓝色电路）是一个极端：它可以通过基础组装机、EM工厂、或低温工厂制造，再加3种不同的品质目标 × 2种增产剂模式 = 约18种有效配置。

#### Satisfactory：106替代配方的组合空间

Satisfactory拥有该类型最广泛的**系统化**替代配方系统。不同于Factorio的零星替代，Satisfactory将其做成核心机制。

**替代配方的6种设计模式**：

1. **消除消耗品**：铸铁螺丝（铁锭→螺丝，跳过铁棒步骤）
2. **替代原料**：铁线（铁锭→线材，消除铜依赖）→ 使"仅用铁矿"的生产链成为可能
3. **提升产出率**：固态钢锭（铁锭+煤→钢锭，产出+33% vs基础配方）
4. **改变建筑类型**：纯矿石配方（精炼厂中矿石+水→锭，输出更多但消耗电力+占用空间）
5. **引入反馈循环**：回收塑料/回收橡胶循环（塑料+燃油→2×橡胶；橡胶+燃油→2×塑料）
6. **整体链简化**：马虎氧化铝+纯铝锭将铝链从4输入（铝土矿+水+煤+硅石）塌缩为仅铝土矿+水

**"仅用铁矿的重型模块化框架"——涌现的元策略**：

```
标准重型模块化框架链：
  铁矿+铜矿+煤矿+石灰石 → 多种中间产物 → 重型模块化框架

仅用铁矿+石灰石的链：
  基础：铁锭, 铁板, 混凝土
  + 铁线替代配方（消除铜）
  + 缝纫铁板替代配方（消除螺丝）
  + 铁管替代配方（消除煤→钢管步骤）
  + 套管工业管替代配方（消除钢梁步骤）
  + 重型套管框架替代配方 → 仅需模块化框架+套管梁+铁管+混凝土
= 仅输入：铁矿石+石灰石
```

这不是设计师有意创造的"成型方案"——它涌现自5个独立设计的替代配方的组合。整体大于部分之和。

**配方路径多重性指标**：

| 游戏 | 每条最终产品的平均路径数 | 最大路径数（单产品） | 替代配方解锁机制 |
|------|:--:|:--:|------|
| Factorio | ~2-3 | ~18（处理单元，跨机器+品质+产能） | 科技树+太空探索 |
| Satisfactory | ~3-5 | ~30+（重型模块化框架，考虑所有替代组合） | 探索→硬盘→RNG选择 |
| DSP | ~1.5-2 | ~5（处理器，罕见矿脉+增产剂模式） | 星际探索+矿脉发现 |
| CoI | ~1.2-1.5 | ~3（钢，不同熔炉/裂解路线） | 科技树 |
| Mindustry | ~1（仅直链） | ~2（石墨，按压机或水压机） | 科技树 |
| ONI | ~3-5 | ~10+（O2产生方式：电解/藻类/锈蚀/污染氧→纯净氧...） | 科技树+生物突变+物理约束 |

#### DSP稀有矿脉——"更短配方"vs"更好配方"

DSP贡献了一个根本不同的替代配方理念：稀有矿脉不是让你更高效地制造物品——它们是**完全移除链中的步骤**。

```
标准有机晶体链（无稀有矿脉）：
  原油→精炼油→塑料→有机晶体（11台精炼厂+6台化工厂，210原油/min+30水/min，6秒一个晶体）

有机晶体矿脉链（有稀有矿脉）：
  矿机→有机晶体（1台建筑，0原油，0水，0石油衍生物，2秒一个晶体）
```

这与Factorio的Kovarex浓缩或Satisfactory的固态钢锭根本不同——后者是"同一个物品，更好的生产成本"，DSP稀有矿脉是"同一个物品，更短的链"。这种设计将行星探索与工厂设计深度绑定——选择下一次前往哪里的战略决策取决于"这颗行星上有哪种链缩短矿物"。

#### ONI——突变生物形态作为并行生产路径

ONI中的平滑哈奇（Smooth Hatch）是配方替代的独特形式：它不是蓝图中放置的建筑，而是一只**动物**，通过进食代谢输入产出输出。

| 哈奇形态 | 食性 | 产出 | 精炼金属路径 |
|---------|------|------|-------------|
| 哈奇（基础） | 矿物→煤 | 无精炼金属 | 无 |
| 石壳哈奇 | 矿物+沉积岩→煤 | 无精炼金属 | 无 |
| 光滑哈奇 | 金属矿石→精炼金属 | **75%矿石质量的精炼金属** | 代谢精炼（无热、无电、100%效率...但慢且依赖繁殖） |
| 金属精炼厂 | N/A | 100%矿石质量的精炼金属 | 机械精炼（产生热、需电、100%效率+潜在冷却水） |

光滑哈奇是对金属精炼厂的平行替代——但具有根本不同的约束（生物繁殖周期、放牧劳动、温度范围限制）与收益（无热管理、无电消耗）。这是一个**活的配方**，与建筑配方竞争。

### 3.2 跨配方耦合

配方不是孤岛。改变一个配方会通过共享中间产物波及整个系统。

#### 石油/流体耦合——最经典的跨配方依赖

**Factorio石油耦合网络**：

```
原油 → 高级石油加工 → 重油 → [润滑油] → 电动引擎 → 飞行机器人框架
                    ↘ [裂解] → 轻油 → [固体燃料]
                    ↘ 轻油 → [固体燃料] → [火箭燃料]
                    ↘ [裂解] → 石油气 → [塑料] → 红电路/LDS
                                       → [硫磺] → 硫酸 → 蓝电路/电池/铀矿
                                       → [固体燃料]（低效溢流吸收）
```

一个下游消费者的变化波及整个系统：
- 润滑油需求增加（升级蓝带）→ 更多重油被消耗 → 更少重油裂解为轻油 → 轻油可用量下降 → 固体燃料生产下降 → 火箭燃料生产下降 → 火箭发射减缓
- 这被称为"石油死锁"——因为流体系统的背压机制（任何输出满则所有输出停），不均衡通过共享流体双向传播

**CoI——维护与柴油的耦合**：

CoI通过两种通用资源实现了**全配方耦合**：维护（间接消耗铁+铜）和柴油（间接消耗原油）。CoI中几乎每条配方链都物理上依赖于卡车运输，卡车消耗柴油和维护。这意味着：

```
任何配方的扩展
  → 更多建筑消耗维护
    → 需要更多铁+铜矿开采
      → 需要更多矿场（消耗维护+柴油用于运输）
        → 需要更多维护生产（消耗维护+柴油）
          → 需要更多柴油生产（消耗维护+柴油）
            → 递归直到系统崩溃或达到平衡
```

这被称为"并行资源经济"——"生产经济"（制造产品）和"维护经济"（维持机器运行）持续争夺相同输入。这与Factorio的根本区别在于：在Factorio中，如果铁板生产停止，**仅**铁板消费者停止。在CoI中，如果铁板生产停止 → 维护生产停止 → 所有建筑开始故障 → 整个工厂瘫痪。故障是**传染性的**。

**ONI——热力耦合**：

ONI有该类型中最**通用的**耦合层：热。每个转化都有热特征（产生热、删除热、或热中性）。将所有转化连接在一起的图不是物品图——是**热图**。

```
热源（天然气发电机、金属精炼厂、电解器、变压器）
  → 热量通过共享环境（气体/液体/固体）中的导热传播
    → 加热共享冷却回路中的液体
      → 蒸汽涡轮从高温蒸汽中回收电力
        → 电力回到冷却系统
        → 热通过辐射管排入太空
          → 所有热产生者的净热预算必须<排热能力否则系统过热
```

关键洞见：单条建筑链的热特征不能被孤立评估。一个金属精炼厂产生16 kDTU/s。一个天然气发电机产生10 kDTU/s。如果这两者共享一个冷却回路，那么回路必须能够处理至少26 kDTU/s——这不是任何一个**配方**的属性，而是工厂**布局**的属性。热耦合是涌现的——它从同一物理空间中布置转化的事实中自发产生。

**耦合强度矩阵**：

| 游戏 | 耦合机制 | 耦合强度 | 波及传播速度 | 故障传染性 |
|------|---------|:--:|:--:|:--:|
| Factorio | 共享中间产物（固体+流体） | 中 | 中（缓冲区延迟） | 低（铁停止不停止铜） |
| CoI | 维护+柴油（全局资源） | **极高** | 快（维护缓冲区小） | **极高**（死亡螺旋） |
| ONI | 热（物理传播）+ 气体压力 | 高 | 中（导热率限制） | 高（过热连锁） |
| Satisfactory | 共享中间产物 + 电力（超频） | 中 | 慢（大型缓冲区） | 低（电力不足=降速，非故障） |
| DSP | 共享物流网络（ILS/传送带） | 低-中 | 中 | 低 |
| Mindustry | 共享资源节点（矿脉） | 低 | 慢 | 低 |

### 3.3 配方模块化与蓝图

蓝图系统是配方的**封装层**——它将一个复杂的子工厂转化为可重复使用的黑箱。蓝图能力直接影响玩家能管理的复杂度上限。

| 游戏 | 蓝图系统 | 封装程度 | 最大蓝图尺寸 | 跨存档复用 |
|------|---------|:--:|------|:--:|
| **Factorio** | 完整蓝图+蓝图本+控制参数 | 极高：支持电路条件、模块配置、列车站点命名 | 无上限 | 是（全局蓝图库/蓝图字符串） |
| **Mindustry** | 示意图（Schematic）系统 | 高：编码建筑位置+旋转+配置+传送带路线 | 受限于单张地图 | 是（编码字符串+.msch文件） |
| **Shapez 2** | 蓝图+平台复制 | 高：复制完整生产模块 | 无上限 | 是 |
| **DSP** | 社区蓝图模组 | 中：复制建筑布局+传送带+分拣器 | 行星级 | 社区网站分享（dysonsphereblueprints.com） |
| **Satisfactory** | 蓝图设计器（5×5/6×6） | 低：极小尺寸限制，无法跨蓝图层连接传送带/管道 | 6×6基础（最大） | 是（但限制使大型复用困难） |
| **CoI** | 蓝图（内置） | 中：复制建筑+配置，管道连接保留 | 中等 | 是 |
| **ONI** | 蓝图模组（社区） | 中：依赖模组 | N/A | 部分 |
| **Riftbreaker** | 建筑模板 | 极低：仅建筑组，不包含物流 | N/A | 是 |

**蓝图系统对配方深度的影响**：

1. **Factorio的蓝图使配方缩放成为可能**。如果没有蓝图，设计一次3:2绿板集群是令人满意的。设计第五十次则是折磨。蓝图将配方求解（有创造力、有趣的）与配方缩放（机械的、重复的）分离。这使Factorio能够保持比任何其他游戏更高的配方复杂度。

2. **Satisfactory的弱蓝图是其3D视角的牺牲品**。在3D中，蓝图对齐、地形适应、和传送带连接比2D复杂一个数量级。设计师选择了保守的蓝图能力（小尺寸、无跨单元连接）并依赖Overclocking/Underclocking来处理缩放——这让单个建筑更强大，但限制了模块化重用。

3. **Shapez的MAM（万能制造机）是"配方的配方"**——一个通过信号网络可编程的工厂，可以生产**任何**形状。MAM代表配方封装的理论极限：它不封装单个配方，而是封装**所有可能的配方**（在操作闭包内）。

## 四、涌现能力分析

### 4.1 涌现复杂度定义

我们需要区分四种涌现实例：

| 涌现类型 | 定义 | 实例 |
|---------|------|------|
| **设计涌现** | 设计师预见并从系统规则中推导出的复杂度 | Factorio的石油配平谜题；Satisfactory的铝链水循环 |
| **玩家涌现** | 玩家发现的设计师未预期的意外解决方案 | ONI的SPOM（自供氧模块）；Shapez的销塔漏洞 |
| **规模涌现** | 小规模可忽略的因素在大规模变为核心约束 | Satisfactory的传送带吞吐量上限（780/min→影响配方选择） |
| **组合涌现** | 两个独立系统交互产生全新的玩法维度 | Factorio品质+回收+产能模块→升级循环元游戏 |

### 4.2 各游戏涌现潜力排名

#### 1. Factorio — 品质+电路+模块+物流 → 最高

Factorio的涌现潜力居首，因为**每个子系统都与其他子系统可组合**：

**涌现实例1：品质升级循环（Space Age）**

两个独立系统——回收器（返回25%原料）和品质模块（随机提升输出品质）——最初被设计为独立功能。但当玩家将它们组合时：

```
制造（品质模块）→ 过滤：保留传说级，回收其他
  → 回收器（品质模块）→ 返回更高级原料
    → 制造（品质目标）→ 使用更高级原料产出更高级物品
      → 循环 → 传说级产出
```

这创造了一种全新类型的生产链——不是线性变换，而是**统计性反馈循环**。最优模块配置（1品质+4产能@传说级T3模块）约产生2.72%的传说级输出/次，总资源成本约为标准成本的56倍。设计师预期了回收器+品质的交互，但意想不到的结果是**升级循环本身就是一项可优化的工程挑战**——催生了社区中的传说级效率竞赛。

**涌现实例2：仅用火车物流的大型多基地工厂**

设计师预期玩家使用火车运输散装矿石。他们未曾预期玩家完全消除传送带干线，使用完全由专用小工厂+列车连接组成的"城市街区"设计。每列火车成为高吞吐量的"传送带"，蓝图块成为"配方单元"。结果规则——街区尺寸匹配列车长度，交叉路口吞吐量设限——是涌现的，不在任何配方中指定。

**涌现实例3：与外星物流的电路控制配方切换**

Factorio的可编程电路允许通过信号触发配方变更（通过在不同物流网络之间切换或控制插入器过滤器）。这结合工厂蓝图产生"可重编程的工厂模块"，可以根据需求动态改变其输出组合——这是设计师提供工具但未设计具体行为的一个涌现实例。

#### 2. Oxygen Not Included — 物理模拟 → 极高

ONI的涌现潜力来自于其物理引擎的非线性——转化不是在真空中发生的，而是在共享物理空间中发生的。

**涌现实例1：SPOM（自供氧模块）**

标准的电解器+氢气发电机+气泵排列：
```
电解器：H₂O → O₂（888g/s）+ H₂（112g/s）
氢气发电机：H₂ → 800W 电力 + 无副产物
气泵+分拣器消耗 < 800W

净效果：模块产生O₂且免费运行（电力自维持）
```

设计师创造了电解器和氢气发电机作为独立的游戏循环元素。SPOM并非他们设计的"预期"构建——它是玩家发现的物理规律的自然结果（电解产出足够的氢气以驱动分离气体所需的泵和发电机）。

**涌现实例2：工业桑拿（Industrial Sauna）**

将所有发热工业建筑封装在一个密封的蒸汽室中：
```
熔炼厂 + 发电机 + 精炼厂 → 产生废热
  → 加热密封室中的蒸汽
    → 热蒸汽驱动蒸汽涡轮 → 回收电力
      → 蒸汽凝结为水 → 水循环回冷却回路
```

这种设计将"多余热量"（大多数玩家认为是一种危害）转化为"另一种电力来源"。它是涌现的，因为热管理被设计师设计为**约束**——不是电力产生机制。玩家反转了问题的符号。

**涌现实例3：石油锅炉（逆流换热）**

```
预热原油 → 滴在>400°C热板上 → 闪蒸为石油 → 热石油逆流预热输入原油 → 冷却石油输出
```

这个反直觉的设计（将冰 COLD 原油变为 400°C 的石油，并以 100% 转换效率和净能量正产出）利用了精确的反向逆流换热。所使用的物理定律是设计师设定的，但这一具体实现——达到 100% 的近理想热力学效率——在游戏设计中并未被规划。

**物理规律作为"元涌现层"**：ONI 具有涌现，因为给定了基本物理规律（热力学第一定律、热方程、道尔顿分压定律），玩家可以在设计师设定的建筑组合规则中发现新颖的组合。建筑是"点产品"——物理则是构建它们的**连续空间**。

#### 3. Shapez 2 — MAM → 高

**涌现实例1：万能制造机 (MAM)**

MAM 是一台"可以制造任何形状的工厂"。它读取枢纽的当前目标形状代码作为线信号，将其虚拟解构为各层的各个象限，使用由信号总线驱动的比较器和过滤器选择正确的形状类型和颜色，然后独立处理并逐步组装成完整的输出形状。

MAM 是**涌现的**，因为 Shapez 的游戏机制定义了形状、变换和信号——但 MAM 是一种自适应生产系统，这意味着"任何配方都可以由通用机器自动执行"是**玩家推导出的定理**，而非设计师放置的目标。设计师设定了约束（形状必须由切割/旋转/堆叠/上色构建）、定义了信号系统，但让玩家去发现："一个单个、不修改的工厂能否生产任意形状？"——答案是"能"。

**涌现实例2：销塔漏洞 (Pin Tower Exploit)**

在 Shapez 2 中，销 (Pin) 每次推入会去掉一层，将形状堆到四层以上。通过在一个形状上叠加四个销，再将得到的四层"销塔"切成四个独立的单层销，玩家可以产生一个完整层，每个位置都有销。这将"破坏超出层数上限"的副作用转化为**资源复制技术**——这属于典型的玩家涌现。

#### 4. Captain of Industry — 死亡螺旋 → 高

**涌现实例1：死亡螺旋**

这不是预设的脚本事件——它从系统交互中涌现：

```
1. 原油储备意外耗尽（低估蒸馏需求）
2. T+5min: 柴油储罐干涸。所有卡车燃料不足。
3. T+10min: 铁矿石的采矿卡车停运。维修零件组装停止。
4. T+15min: 所有建筑的维修水平开始下降。矿工最先故障。
5. T+20min: 随机故障在电炉、化工厂、食物加工厂蔓延。
6. T+25min: 食物生产停止。人口健康指数崩溃。工人死亡。
7. T+30min: 劳动力减少 → 无法配置足够建筑来恢复 → 游戏结束
```

死亡螺旋涌现自四个递归依赖：维修是递归的（维修消耗投入品生产维修，这些投入品需要建筑运营）、燃料是递归的（柴油驱动运输柴油的卡车）、人口是递归的（食物生产需要柴油和维修）、副产品堵塞是递归的（废液满箱 → 逆向堵塞精炼厂 → 主产品生产停止）。

**涌现实例2：酸水→硫磺→矿渣级联**

```
原油蒸馏 → 酸水（危险废物流）
  → 酸水汽提器 → 硫磺（过量）+ 氨
                   ↓
         硫磺 + 石灰石 → 矿渣（无限产生）
                          ↓
              碎石机 → 矿渣碎石 → 混凝土板（需求激增时有用）
                          ↓
              填海造地（永久消耗、无污染）
```

硫磺（一项设计好的伤害惩罚）可以被转化为矿渣，用于**扩展可建造土地**。这是惩罚（硫磺处理）转化为一个奖励（免费填海材料）的涌现——副产品管理促使玩家发现正反馈循环。

#### 5. Satisfactory — 替代配方组合 → 中-高

**涌现实例1：仅用铁矿的重型模块化框架**

已在第3.1节详述。这是涌现的元策略，源自5个独立替代配方的组合。

**涌现实例2：回收塑料/橡胶循环**

```
塑料（30）+ 燃油（30）→ 回收橡胶 → 60 橡胶
橡胶（30）+ 燃油（30）→ 回收塑料 → 60 塑料
         净产出：燃油 → 2 × 塑料或 2 × 橡胶
```

基础配方：30 原油 → 30 塑料（或橡胶）。全替代配方链：30 原油 → ~90 塑料+橡胶当量。这是将约3倍的产出倍增——不是通过任何单个强大的替代配方，而是通过链式组合。塑造这个最优配置的精确燃油消耗约束使得这成为一个深层的系统工程难题。

**涌现实例3：AWESOME 沉淀池作为"副产品溢流阀"**

满意工厂的副产品通常不存在——但石油加工中的聚合树脂是一个半副产品（必须持续消耗以防止精炼厂阻塞）。AWESOME 沉淀池（将任何物品转化为优惠券点数，无限容量）将一个阻塞问题转化为一个无界资源吸收池。设计师将沉淀池设计为溢流阀，但其"将废料转化为积分"的涌现特性使得"沉掉一切多余"成为一种普遍的优化策略。

### 4.3 涌现的推动者与阻碍者

#### 推动涌现的设计选择

| 推动者 | 作用机制 | 最高应用案例 |
|--------|---------|------------|
| **开放配方图（多路径）** | 玩家可以从多个方向探索同一问题的解 | Satisfactory 的替代配方 |
| **多输出配方** | 强制处理废物，废物→有用循环的涌现 | CoI 的酸水→硫磺→矿渣→填海 |
| **可编程控制（电路/逻辑）** | 允许由信号驱动的自适应配方行为 | Factorio 的电路控制工厂；Mindustry 的逻辑处理器 |
| **物理模拟层** | 热、压力、重力创造非配方变换规则 | ONI 的 SPOM、工业桑拿 |
| **可组合的原语（小、正交的操作）** | 玩家可以组合原语产生新颖的变换 | Shapez 的 4操作 → MAM |
| **Mod API（开放原型系统）** | 社区添加新配方、物品、建筑，指数级扩展组合空间 | Factorio 的 Pyandon 等 |
| **蓝图/封装** | 玩家可以将复杂解封装为可重用模块 | Factorio 的蓝图本；Mindustry 的示意图 |

#### 阻碍涌现的设计选择

| 阻碍者 | 作用机制 | 最低应用案例 |
|--------|---------|------------|
| **单一路径配方图** | 无选择 = 无涌现 | Riftbreaker（每物品一条链）、Planet Crafter |
| **不可配置建筑** | 建筑固定行为 = 无自适应 | Mindustry（每工厂一个配方） |
| **缺少逻辑层** | 无信号或编程 = 无动态行为 | Riftbreaker、Plan B、Planet Crafter |
| **缺少蓝图** | 复杂解不能被复用 → 复杂度上限被束缚 | Planet Crafter（无自动化至深局末） |
| **副产品可销毁（无惩罚）** | 副产品管理永远产生紧急涌现 → 但被消除了 | Factorio 废料（无）；Satisfactory（几乎不存在） |
| **全局库存取代物流** | 消除空间维度 → 消除空间涌现 | Riftbreaker、Planet Crafter |

## 五、Mod 扩展能力对比

### 5.1 Mod 架构分级

| 级别 | 特征 | 代表游戏 |
|:--:|------|------|
| **Lv5: 一等配方原型系统** | 官方 API，Mod 配方与官方配方同权。数据驱动的原型定义（Lua/JSON）。Mod 完全控制配方图、建筑类别、科技树。多个修改可以在数据阶段共存。 | **Factorio** |
| **Lv4: 开放架构 + 社区逆向框架** | 无官方配方 API，但引擎开放（Unity/Unreal） + 社区构建了稳定的 Mod 加载器和内容注册表。需编程（C#/C++/Blueprint）。 | **DSP**（BepInEx+LDBTool）、**Satisfactory**（SML）、**Shapez 2**（C# API） |
| **Lv3: 官方 Mod 支持受限** | 有 Mod 接口（JSON/JS/Steam Workshop），但配方修改能力存在硬性限制。只能添加或修改有限集合的配方属性。 | **Mindustry**（JSON/HJSON+JS）、**ONI**（Steam Workshop+Klei API）、**CoI**（实验性C# API） |
| **Lv2: 仅关卡/地图 Mod** | 不能添加新配方或物品，只能修改关卡数据（输入形状、目标形状、地图布局）。 | **Infinifactory**（Steam Workshop）、**Railgrade**（关卡编辑器） |
| **Lv1: 无 Mod 支持** | 完全封闭。游戏内容硬编码。 | **Planet Crafter**、**Assembly Line 1/2**、**The Riftbreaker**、**Plan B: Terraform** |

### 5.2 Factorio Mod 配方生态深度分析

Factorio 的 Mod 生态系统是工业自动化游戏中的黄金标准。

#### 原型系统架构

Factorio 使用三层数据加载阶段：

```
数据阶段加载顺序：
1. data.lua（所有 Mod 初始定义）
2. data-updates.lua（在所有 data.lua 之后运行 → 可以修改其他 Mod 的定义）
3. data-final-fixes.lua（在所有 data-updates.lua 之后运行 → 最后的调整）

控制阶段（control.lua）：
- 原型是只读的、不可变的
- 无法在运行时更改配方成分、制作时间、或类别
- 变通方案：预定义多个原型变体并通过脚本在不同变体之间切换
```

#### 可自由定义的配方属性

```lua
-- 一个 Mod 可以定义的最小配方
data:extend{{
  type = "recipe",
  name = "my-custom-item",
  category = "crafting",  -- 或 "chemistry", "smelting", 任何自定义类别
  enabled = true,         -- 科技树中初始可用
  energy_required = 5.0,  -- 制作时间（秒）
  ingredients = {
    {type="item", name="iron-plate", amount=4},
    {type="fluid", name="lubricant", amount=25}
  },
  results = {
    {type="item", name="my-custom-item", amount=1},
    {type="item", name="iron-gear-wheel", amount=1, probability=0.3}  -- 30% 产出额外物品
  },
  main_product = "my-custom-item",
  allow_productivity = true,     -- 允许产能模块作用
  allow_quality = true,          -- Space Age 2.0
  auto_recycle = true,           -- 自动由品质系统生成回收配方
  subgroup = "my-mod-group",
  order = "a[my-custom-item]",
  emissions_multiplier = 1.5,    -- 污染倍数
}}
```

#### 标志性大修 Mod 生态层级

Mod 生态形成了一个清晰的复杂度金字塔：

**第1层：原版扩展（Krastorio 2）**
- +4新资源（稀有金属 + imersite + 矿物水 + 修改后的石油/铀）
- +40新建筑，+100新技术，+300+新图标
- 修改原版配方以创造更连贯的进阶
- 引入物质转换终局玩法
- 配方空间 ≈ 原版的1.5-2倍
- 延长约2倍游戏时间

**第2层：多模组合复刻（Bob's + Angel's）**
- Bob's：13+新矿石（锡、铅、银、金、钨、镍、锌、钴、铝、钛、硅等），5层等级建筑，8层模块层级
- Angel's：用6种复合矿石（saphirite、stiratite等）替代所有标准矿石，4层精炼链（破碎→块→晶体→提纯），Angel's 石油化工添加30+新流体/气体
- 组合：200+新配方、500+新物品、从矿石到可用的板材需要10+步
- 配方空间 ≈ 原版的3-5倍

**第3层：星球间物流层（Space Exploration）**
- 600+行星系统，20+新型科学包
- 行星专属资源（cryonite、vulcanite、beryllium、holmium、iridium、vitamelange、naquium）
- 星际配方链：在外围行星开采→ 通过货船运送到太空平台 → 与其他行星资源组合 → 高级科学包
- 8种 Arcosphere（epsilon、lambda、gamma、xi、zeta、theta、phi、omega）：在深层空间科学中被**转换**（而非消耗），通过折叠/反演配方在类型之间转换，形成一个8维平衡谜题
- 配方空间 ≈ 原版的3-4倍，加上强烈的空间分离

**第4层：极致复杂度（Pyanodon's）**
- 数千配方复制真实工业化学、生物学、材料科学
- 几乎每个配方都有副产品——"垃圾管理"是核心挑战
- 4层等级建筑系统，提升效率需要越来越复杂的材料
- 11种科学包类型（原版7种）
- 铁矿起步为8:1比例（矿石:板材），可升级至5+以上，需经10-20步处理链
- Alien Life 包添加具有品种、基因操作、生长周期的生物元素
- 预计游玩时间：1000+小时
- 配方空间 ≈ 原版的10-20倍。分支因子是真正的复杂度倍增器。

**第5层：约束开始复刻（Seablock、Nullius）**
- **Seablock**（基于Bob's+Angel's）：从单个1格岛屿开始。所有资源从水中提取。填海造地必须制造以扩展工厂。2种水类型（常规、粘性/矿化）是唯一输入。电力是第一危机：藻类→木炭循环是高度水密集型且能量几乎持平。所有矿石从矿化水→矿石分选→精炼链制造。配方约束：一切追踪回水。
- **Nullius**：设定在无化石燃料、无氧气、无生命的死亡世界。"副产品优先设计"：几乎所有配方都产生必须管理的多重输出。销毁是必要的，但某些材料（二氧化硅）不能销毁——必须回收。产出提升伴随更多副产品，迫使持续重设计。防止"复制粘贴"式建厂——每个生产块必须独特设计以处理其副产品流。

#### Mod 配方兼容性机制

当多个 Mod 共存时，Factorio 使用以下策略：

1. **加载顺序依赖**：Mod 声明依赖关系（`info.json`）。在 `data-updates.lua` 中加载的 Mod 在所有 `data.lua` 文件之后运行，`data-final-fixes.lua` 最后运行。允许 Mod 检查 `if mods["other-mod"] then` 并条件性地调整配方。

2. **配方名称冲突**：如果两个 Mod 都定义了 `recipe["steel-plate"]`，最后加载的优先级覆盖。为避免冲突，Mod 使用条件检查：`if not data.raw.recipe["my-item"] then` 或者修改现有原型。

3. **物品替换**：当 Angel's 检测到 Bob's Mod 时，将配方输出中的原版物品替换为 Bob's 的变体。

4. **配方类别桥接**：兼容性 Mod 向现有机器添加新配方类别，或向现有配方添加新机器的类别，桥接两个未设计为协同工作的大修 Mod。

5. **硬编码限制**（Mod 无法通过任何手段绕过的限制）：
   - 品质层被硬编码上限5层——无 Mod 可添加"神话级"或"神级"品质层
   - 原型在运行时不可变（根本引擎约束）
   - 概率配方限于单输出的随机化（铀风格）——无加权多输出概率
   - 配方类别对产能模块的限制不可定制
   - 流体温度可以指定在配方中，但不得以动态方式改变
   - 制作时间下限为 1 tick（1/60秒）——无亚tick配方

### 5.3 其他游戏的 Mod 配方能力

#### Dyson Sphere Program

- **框架**：BepInEx（Unity Mod 加载器）+ LDBTool（核心 Mod 库，使 Mod 可以添加/编辑 Proto 数据）+ CommonAPI（用于注册新配方类别和自定义机器行为的高级库）
- **配方 Mod 能力**：可通过 C# 代码添加新物品、配方、建筑类别、科技树节点。稀有资源配方、新增分馏配方（FractionateUniverse 添加 34 个分馏配方）。GenesisBook（105k+ 下载量）代表最接近"全面修改"的内容扩展。
- **限制**：没有像 Factorio 那样的数据阶段。所有 Mod 在游戏加载其内部数据后通过 C# 代码修改。多个配方修改竞争时有负荷顺序问题。矩阵配方（科研矩阵）通过标准 API 不可修改——硬编码。反作弊验证会检查特定物品的资源收集 vs 生产平衡——覆盖核心配方可能触发此检查。

#### Satisfactory

- **框架**：SML（Satisfactory Mod Loader）+ SMM（Satisfactory Mod Manager，社区构建的桌面应用）+ ficsit.app（社区维护的 Mod 仓库）
- **配方 Mod 方法1（ContentLib）**：JSON 文件定义新物品/配方/里程碑（科技 Hub）。可修改现有物品/配方/里程碑的属性。热重载支持。**限制**：不能添加新的 3D 模型、不能创建新建筑类型、不能添加新的游戏机制——配方只能目标已存在的建筑类型。
- **配方 Mod 方法2（Unreal Editor + C++/Blueprint）**：可以创建全新的带有自定义网格、动画和机器逻辑的建筑。自定义 `FGRecipe` 子类任意行为。可变功率配方。无引擎级 API 限制——整个游戏可修改。需要 Unreal Editor，门槛显著更高。
- **标志性 Mod**：Satisfactory Plus——大规模修改 Mod，改变几乎所有原版配方和产出率，从 T1 延伸到 T6，添加 24 种替代配方。这是"Satisfactory 的 Bob's/Angel's"——代表了配方修改能达到的上限。
- **限制**：服务器上所有玩家必须有相同版本的相同 Mod。移除内容 Mod 可能损坏存档（物品/建筑/配方写入存档文件）。游戏更新可能暂时破坏 Mod。没有官方 Mod API——一切基于逆向工程 C++ 头文件和 Blueprint 反射构建。

#### Mindustry

- **框架**：JSON/HJSON 驱动的内容定义 + Java/JS 逻辑（通过模组目录结构）
- **可定义的配方属性**：`GenericCrafter` 输入（items、liquids、power）、输出 item/liquid、制作时间、建筑大小、特效类型
- **可用的建筑类型**：`GenericCrafter`、`GenericSmelter`、`Separator`（概率输出）、`HeatCrafter`（Erekir 风格热力需求）、`AttributeCrafter`（效率依赖于地形格类型）
- **硬限制**：每个工厂类型只能有一个配方。无法制作多配方工厂（类似 Factorio 的组装机）——这是引擎的硬约束。逻辑处理器限制（1000 指令、16KB 压缩代码、6000 连接）是防滥用硬限。Erekir 的核心卸载规则无法通过 Mod 改变。

#### Oxygen Not Included

- **框架**：Steam Workshop + Klei 的 mod API（C# 钩子结构）
- **能修改的内容**：建筑属性（功率、产出率、温度范围）、添加新建筑和转化、新生物、新世界生成规则、UI 修改
- **硬限制**：物理引擎是硬编码的（热传导方程、相变阈值、气体扩散）——Mod 无法改变基础物理规律。单线程物理引擎约束——无多线程 Mod。管道/通风口网络逻辑在引擎级别，Mod 可配置但不可替换。温度→相变映射是数据驱动的（每物质）但相变的**功能**（冷却时凝固、加热时蒸发）是硬编码的。

### 5.4 Mod 生态对配方深度的影响

**"Mod 乘数效应"**衡量：与原版相比，Mod 增加了多少配方深度。

| 游戏 | 原版配方深度 | Mod 后深度 | 乘数 | 说明 |
|------|:--:|:--:|:--:|------|
| **Factorio** | 9/10 | 11/10（无限） | **∞** | 原版极深。Mod 添加无限深度。最大差距。 |
| **Mindustry** | 6/10 | 7/10 | ~1.2x | Mod 增加内容但引擎限制（一工厂一配方）限制深度扩展 |
| **DSP** | 7/10 | 7.5/10 | ~1.15x | 有一个适度的配方 Mod 场景。无 Level 5 全面的内容复刻。 |
| **Satisfactory** | 7/10 | 8/10 | ~1.2x | Satisfactory Plus 增加了显著深度，但规模和生态远小于 Factorio |
| **ONI** | 8/10 | 8.5/10 | ~1.1x | Mod 扩展内容但不改变配方架构 |
| **Shapez 2** | N/A（操作深度） | 8/10 | ~1.5x | Mod API 允许新操作——显著扩展 |
| **CoI** | 8/10 | 8.5/10 | ~1.1x | 实验性 API 尚未催生大型内容复刻 |
| **其他（Riftbreaker、Planet Crafter 等）** | 3-5/10 | 同左 | 1x | 无 Mod 支持，无乘数 |

**关键洞见**：Factorio 从 Mod 中的获益**超过**该类型的任何其他游戏——并且差距正在扩大。原因是 Factorio 的 Lua 原型系统呈现了一个"配方组合器"模型，使得 Mod 配方与官方配方**数据等效**。一个 Pyandon 配方与一个原版 Factorio 配方全权相等——引擎以相同方式处理两者。这在 DSP 或 Satisfactory 中不成立——Mod 配方是二等公民，通过逆向工程的 C# 钩子工作。

## 六、配方设计模式总结

### 6.1 十大配方设计模式

#### 模式1：科技包门控模式 (Science Pack Gating)

**使用**：通过要求复杂配方产出的物品来解锁科技，推动玩家自动化。

**实例**：
- Factorio：7种科学包类型（红/绿/蓝/紫/黄/白/农业）。每一种都要求比前一种更深的生产链。蓝科学包（流体首次出现）是著名的"墙面"——玩家留存掉落的峰值时间点之一。
- DSP：5种彩色矩阵 + 反物质白矩阵。矩阵等级系统创建了一条确定的生产链深化路径。
- Satisfactory：太空电梯阶段（哈勃终端零件）+ 里程碑 + MAM 研究树 + 硬盘驱动扫瞄。同时具有**多种**门控机制（科技、阶段零件、MAM 研究、替代配方解锁）。

**为什么这是模式**：它通过不让科技树成为可跳过的菜单，将配方系统与进阶系统连接起来。科学生产规模变得如此之大，以至于它决定了整个工厂拓扑。

#### 模式2：副产物强制管理模式 (Mandatory Byproduct Management)

**使用**：配方产生必须处理的副产出流。

**谱系**：
- **极度**（CoI）：几乎所有配方产生废物（废气、矿渣、酸水、有毒泥浆、赤泥）。每个废物类型都需要专用的处理基础设施。未处理的废物会主动使主产出生产瘫痪。
- **高度**（ONI）：大多数转化产生副产物气体/液体。压力超载停止生产。废物管理是一个物理约束（气泵和过滤器），而非仅需比例的约束。
- **中度**（Factorio）：石油处理仅产生3个副产物（重油、轻油、石油气），必须全部消耗或裂解降级。铀回收再处理。Space Age 的 Gleba 腐坏处理是一类新型副产物管理（基于时间的腐坏）。
- **低度**（Satisfactory）：仅聚合物树脂和核废料是半副产物。AWESOME 沉淀池将所有"多余的"副产物吸收为积分。
- **无**（Riftbreaker、Planet Crafter、Assembly Line）：完全没有副产物。单输出配方仅此而已。

**设计教训**：副产物管理的强度决定了游戏的"紧张 vs. 放松"轴线。高副产物游戏惩罚规划不充分；低副产物游戏奖励扩展。两个极点从不同类型玩家获得强烈反馈。

#### 模式3：替代配方发现模式 (Alternate Recipe Discovery)

**使用**：替代配方不是解锁而是**被发现**——通过探索、搜索或 RNG 获得。

**实例**：
- Satisfactory 硬盘驱动器：118个坠毁点，2选项 RNG 抽取，可保留选择不立即决定。将探索与工厂设计连接起来。
- DSP 稀有矿脉：在特定行星类型上发现的新矿脉解锁绕过基链的捷径。行星探索直接影响配方拓扑。
- Factorio 品质升级循环：Space Age 2.0 品质模块使随机输出提升成为可能。品质循环是一种由发现驱动的优化空间。
- ONI 突变生物形态：生物消费不同食物产生不同产出。通过繁殖而非科技解锁生物。
- Factorio 煤液化：在科技树上是一种"被发现"的替代方案（中级石油处理），但其配方（煤+重油+蒸汽→油）是独特且需要特定条件启用的。

**设计教训**：基于发现的替代配方引入了**信息不对称**和**延迟奖励**，这对玩家持续的探索动机至关重要。它们将"已知困难问题"（如 处理电路需要更多铜）转化为"我能否找到绕过这个问题的配方？"

#### 模式4：品质/层级递归模式 (Quality/Tier Recursion)

**使用**：一个物品的更高层级需要该物品的较低层级作为输入。

**实例**：
- Factorio 模块层：1级模块→需要4个2级模块→需要16个3级模块。指数输入增长。
- Factorio 品质系统（Space Age）：普通物品→稀有物品→史诗物品→传说物品，通过品质模块统计升级。
- Factorio Kovarex 浓缩：消耗 40 U-235 产出 41 U-235。净平衡在微观世界中。递归催化。
- Shapez 平铺/堆叠：任意层数构成，4层是大多数情况的标准。品质递归用在不同象限的堆叠上。
- CoI 维护层：维护 I → 维护 II → 维护 III。层不互相替代——你必须提供所有三层。类似于模块但消耗而非装备。

**设计教训**：递归配方（输出也是输入）创建了**投入门槛**（启动前需要前置累积）。Kovarex 浓缩需要 40 U-235 才能开始；U-235 以 0.7% 概率产出——统计累积是门槛而非生产吞吐量。

#### 模式5：物理约束替代配方模式 (Physics Constraints as Recipes)

**使用**：转化规则不是硬编码在建筑中的，而是从物理模拟中涌现的。

**实例**：
- ONI 相变：加热污染水至 122.35°C → 蒸汽（99%）+ 泥土（1%）。这不是在任何建筑中定义的——它是热力学涌现。
- ONI 热删除：电解器固定输出 70°C 氧气。喂入 20°C 水 → 净热删除。物理使转化资源循环。
- ONI 逆流换热：利用温度渐变中两种液体的反向排列，实现接近理想的换热效率。不是建筑功能，而是空间设计原理。

**设计教训**：物理约束配方是"元配方"——它们不源自单个建筑而是由系统的物理规律定义。这是不可移植到非物理引擎游戏的一种配方，但创造了不可能被刻意设计的综合深度。

#### 模式6：几何变换组合模式 (Geometric Transformation Composition)

**使用**：基础操作（切割、旋转、堆叠、上色）自由组合产生无数可能的结果。

**实例**：
- Shapez 2：从 4 个基础操作生成 ~10^24 种可能形状。
- Shapez MAM：证明操作集是普遍的——单个工厂生产任意形状。
- Infinifactory 的 3D 变换：焊接+切割+旋转+推动。13 个方块类型，任意 3D 排列。

**设计教训**：几何变换组合是"配方设计的代数"。4 个操作通过组合生成接近无限多样性。这证明了工业自动化游戏不必然需要材料配方——变换的组合性可以达到相同级别的深度和复杂性。

#### 模式7：比例金字塔模式 (Ratio Pyramid)

**使用**：配方被设计为创建一个从基础到高级的比例层次结构，迫使玩家通过线性代数求解。

**实例**：
- Factorio 的电子电路（绿色）3:2 比例。将直接比例配平引入为"你必须计算它"，而非"提示建议它"。
- Factorio 的石油裂解 8:1:7 比例（精炼厂:重油裂解:轻油裂解）。是所有工业游戏中最大的社区计算焦点。
- Satisfactory 的铝链水循环。需要精确计算回流以防止死锁。

**设计教训**：比例谜题是"配方理解"的核心测试。它们创造了至少需要外部计算器才能解决的数学问题——使从"玩一个游戏"到"研究一个系统"的转折点。

#### 模式8：维护资源耦合模式 (Maintenance Resource Coupling)

**使用**：所有建筑消耗一种通用"维护资源"，该资源本身是高端配方产物。

**实例**：
- CoI 维护 I/II/III：生产系统持续消耗维护以运行。闲置建筑以 33% 速率消耗维护——即使不使用也要付出成本。
- CoI 柴油：所有非管道连接的配方隐式消耗燃料来驱动卡车运输。
- CoI 工人/人口：需要食物/水/住房/消费品。劳动力是另一种消耗资源。

**设计教训**：维护创建了一个**并行资源经济**，它与你的"生产经济"（制造产品）争夺相同的基础资源。这是"配方图"与"资源图"的耦合——每个配方的真正成本不仅是投入物品，还有维护、燃料、劳动力。

#### 模式9：稀有资源旁路模式 (Rare Resource Bypass)

**使用**：特定地图位置的特殊资源解锁了链长减半的"捷径配方"。

**实例**：
- DSP 有机晶体矿脉：消除塑料/精炼油/化工链 → 直接采矿产生。节省 18+ 建筑和所有流体管理。
- DSP 刺针水晶：绕过石墨烯+纳米管链。广泛认为是游戏中最强的捷径。
- DSP 单极磁石：超强但极稀有（仅存在于黑洞/中子星附近）。坑了许多新玩家——消耗殆尽而无法补充。

**设计教训**：不是"更好的配方"而是"**更短的配方**"。这种理念与 Factorio 的生产力模块（效率提升）或 Satisfactory 的替代配方（有时更短有时不同）根本不同。DSP 的稀有矿脉是"有条件的链短化"——如果发现了正确的稀有矿脉，一个 6 步链可以塌缩为 1 步。

#### 模式10：蓝图封装模式 (Blueprint Encapsulation)

**使用**：复杂配方链被打包为可重用的"元配方"，可以通过单按钮放置。

**实例**：
- Factorio 蓝图：设计一次 3:2 绿板集群→ 自此重复放置。将配方求解（创造性）与配方缩放（机械性）分离。
- Factorio 升级/降级规划器：将配方映射到其更高/更低层级变体。独立于配方本身的平行"配方变换"层。
- Mindustry 示意图：模块化、可拼接、社区共享。编码为可传输字符串。
- Shapez 平台蓝图：复制粘贴整个生产模块（并非"配方"而是"操作"）。

**设计教训**：蓝图将配方系统从"你能设计什么？"转变为"你能管理多大复杂度？"。没有蓝图时，配方复杂度上限由玩家同时理解每条链的能力决定。有蓝图时，复杂度上限由蓝图本的组织结构决定——高一个数量级。

### 6.2 配方系统设计原则

基于对 15 款游戏的分析，我们总结出 8 条设计原则。

**原则1：配方深度来自于中间产品，而非最终产品。**

最终产品（建筑、装备）创造出"目标"——但不能创造"旅程"。深度在于玩家在原材料和最终产品之间必须经过的转化。Factorio 的 9 步火箭链不是深在"火箭"这一步，而是深在"加工单元→模块→控制单元"这 7 个中间产品。教训：投资中间产品多样性，而非最终产品多样性。

**原则2：可组合性的数量由配方图的类型决定。**

DAG（最多数游戏）→ 玩家必须进行线性规划。带循环的 DAG（Factorio 品质升级、Satisfactory 回收循环）→ 玩家必须解稳态方程。操作树（Shapez）→ 玩家必须进行逆向规划。每一种图类型定义了一种不同的思维模式。混合多种图类型创造深度，但代价是认知负载。

**原则3：替代配方不是越多越好——而是越好。**

Satisfactory 有 106 个替代配方 → 仅有约 15-20 个对任何给定链是决定性的。DSP 有 8 个稀有矿脉捷径 → 每一个都显著且改变了你的策略。"替代配方密度"（影响决策的替代配方数 / 总配方数）比绝对替代配方数量更好的指标。Satisfactory 的密度 ≈ 15%，DSP 的密度 ≈ 70%。
教训：创建少量高影响力的替代方案，而非许多低影响力的替代方案。

**原则4：副产物是设计工具，而非设计缺陷。**

"最佳"的副产物水平不是零也不是极高。它是**足够多以至于创造有意义的工程设计，但足够少以至于可以理解**。Factorio 的石油处理（3 个副产物）是 Golidlocks 区域——每个环节足够简单以理解，但足够复杂以需要专注。CoI 的"一切皆副产物"更加现实，但缩小了受众。
教训：将副产物用作设计工具——作为一种创造"必须管理此物"的时刻的方式，在这些时刻里专注给玩家带来回报。

**原则5：物流层决定配方的感知复杂度。**

同样的配方图放在全局库存（Riftbreaker）与传送带网络（Factorio）与 3D 空间传送带（Satisfactory）中是不同的游戏。物流增加了一个**正交的**复杂度维度，该维度与配方深度成正比。高物流复杂度的游戏倾向于较低的配方复杂度，因为总认知负载需要保持恒定。
教训：调整配方复杂度以考虑物流层的认知负载。

**原则6：可编程控制将配方从"静态图"升级为"动态图"。**

Factorio 的电路网络、Mindustry 的逻辑处理器、和 Shapez 的信号系统都允许在配方之间**运行时切换**。动态配方选择将工厂从"固定的数据流图"转变为"可重编程的计算机"。
教训：在你的游戏中加入一些可编程性——即使是最基础的条件（IF 储罐 > 80% THEN 启用水泵）。它无限地扩大了配方系统的上升空间。

**原则7：物理模拟创造了与配方不同的"元层"乐趣。**

ONI 证明了当配方存在于一个物理世界中时，玩家可以找到不是基于效率而是基于**物理漏洞**的解决方案（SPOM、工业桑拿、石油锅炉）。这些解决方案不是被设计出来的——它们是被**发现**的。物理模拟引入了一个超出手动设计配方范围的全新深度的"游戏"。
教训：如果可行，添加一个物理层（温度、压力、密度、相位）——即使经过简化。它创造了无法刻意为配方设计的发现时刻。

**原则8：Mod API 的多寡并非决定因素——配方原型的数据等效性才是。**

如果 Mod 配方与官方配方在游戏中不是**相同的一等公民**，那么 Mod 生态将永远不会是内容丰富的。Factorio 的黄金标准不是它的 Lua API——而是**"我的 Mod 配方与官方配方无法区分"**这一事实。Mod 配方使用相同的原型结构，以相同的方式出现在相同的科技树 UI 中，并在游戏世界中产生相同的视觉/行为表示。
教训：设计配方注册系统（即使没有完整的 Mod 支持），使得未来添加的 Mod 配方在游戏功能上完全等效于基础配方。

### 6.3 配方系统的未来方向

在分析了 15 款游戏中配方设计的历史轨迹后，我们识别出三个新兴前沿。

#### 方向1：AI 生成的配方

**现状**：所有配方由设计师放置或在 Mod 中由玩家设计师手动定义。

**可能性**：
- **程序化配方生成**：给定一个图复杂性参数，自动生成达到所需链深、多输出节点数、和分支因子的配方图。可以通过约束满足确保可解决性。
- **AI 辅助配方配平**：给定期望的瓶颈位置和目标链深，AI 调整制作时间、产出数量和输入数量，以实现期望的比例谜题难度。
- **动态配方的 AI 选择**：在运行时评估玩家能力并根据其能力选择替代配方（更简单或更复杂的路径）。

**设计挑战**：配方是**有意设计的**，每个都服务于一个特定的教程目标或难度标点。避免随机 AI 生成的配方（并非通过意图塑造玩家体验）至关重要。

#### 方向2：玩家设计的配方

**现状**：仅在技术性的 Minecraft 改版或极少数 Mod 中允许玩家创建新配方（例如，Factorio 的蓝图中存储了配置）。

**可能性**：
- **"配方编辑器"模式**：玩家定义新的转化规则——"消耗 2A + 3B，产出 1C，在制作器类型 X 中制造，制作时间 10 秒"。这实际上是玩家成为 Modder 但没有编码。Factorio 的蓝图字符串展示了社区以游戏发现和共享架构的方式交换这种元数据的潜力。
- **社区配方竞赛**：每周的配方挑战，玩家设计一个配方并展示搭建其生产链的最优方法。这利用竞争性创意进行社区参与。
- **可编程制作器**：类似 Shapez 的 MAM——一个可以根据信号改变其内部的配方目标的可编程组装器。结合 Factorio 的电路网络，这解锁了"一个单一建筑就可以生产数百种物品，由逻辑控制何时生产"的情景。

**设计挑战**：平衡。如何防止玩家只为所有东西定义一个"100→100"的配方？

#### 方向3：动态配方（世界状态感知）

**现状**：配方在游戏过程中是静态的。一旦解锁，它们就永不改变。

**可能性**：
- **行星条件影响产出**：如果一颗行星很热，冶炼配方更快但需要更多冷却。如果一颗行星具有高重力，传送带速度降低 → 影响有效的配方吞吐量。DSP 最接近这一点（行星特征影响太阳能效率，但不影响配方本身）。
- **季节性配方变异**：类似 ONI 的间歇泉（休眠/活动周期）但应用于配方。例如，"在夏季，这个化工厂产出 1.5x 但消耗 2x 水"。
- **市场需求驱动的配方价格**：来自类似《铁路帝国》或《纪元》的经济模拟——如果市场上铁过度饱和，铁产品配方变得不那么有价值（产出经济价值而非工程价值）。
- **配方突变系统**：研究的进展或环境事件可能改变配方——"有机突变已改变你的农场产出[随机属性]"。

**设计挑战**：动态配方在配方稳定性与供应/需求调度之间引入了一个权衡。玩家可能需要库存管理和平滑工具。这从纯粹的"工程解谜"转变为"适应性博弈"。

#### 方向4：跨游戏配方系统互操作性

**可能性**：
- 一个标准化配方定义格式（JSON Schema），用于跨所有游戏交换配方数据。
- 配方图可视化工具和外部比例计算器变得通用——同一个工具可以适用于任何使用标准化配方格式的游戏。
- 这促进了知识在 Modder 社区之间的迁移——一个为 Factorio 设计配方的用户可以为 DSP/Satisfactory/CoI 设计等效配方。

**案例研究**：社区已经接近这一目标（FactorioLab 支持跨 Factorio/DSP/Satisfactory 的比例计算），但没有标准化的数据结构。一个 `recipe.schema.json` 标准化可以解锁社区驱动的跨游戏工具开发。

## 七、流派配方设计的理论总结

### 7.1 配方自由度-复杂度帕累托前沿

我们绘制了 15 款游戏按照"配方自由度"（玩家可以多少种有意义的配方选择）和"配方复杂度"（系统支持多少种配方间交互）的帕累托前沿：

```
                    配方复杂度
                         │
                CoI      │   Factorio
                ONI      │
                         │
                         │   Satisfactory
                         │   DSP
                         │
                         │   Mindustry
                         │   Shapez 2 (非物料配方)
                         │
                         │   Railgrade
                Planet   │   Assembly Line 2
                Crafter  │   Riftbreaker
                         │   Plan B
                         │
                         └────────────────────→ 配方自由度
```

**帕累托最优游戏**（无论按哪个维度都不被其他游戏完全压制）：

- **Factorio**：复杂度和自由度同时达到最高。这是该类型的帕累托最优"天花板"。
- **CoI**：在复杂度上接近 Factorio，但自由度较低（更多约束）。它的帕累托最优是因为在深度-约束权衡中无人支配它。
- **Shapez 2**：自由度极高（你可以制造任意形状），复杂度是在空间操作维度上而非物料配方维度上。在不同的评价指标上实现帕累托最优。

### 7.2 配方设计的"不可能三角"

基于分析，我们假设配方系统设计中存在一个"不可能三角"——一个游戏可以在三项理想属性中至多优化两项：

```
           简单可理解
           /        \
          /          \
         /   选择     \
        /   一项       \
       /   优化两项     \
      /                  \
设计深度              涌现潜力
```

1. **简单可理解 + 设计深度**（牺牲涌现潜力）：清晰而有深度的设计师指导的体验。实例：Mindustry。
2. **设计深度 + 涌现潜力**（牺牲简单可理解）：复杂系统相互碰撞产生令人惊讶的结果。实例：ONI、CoI。
3. **简单可理解 + 涌现潜力**（牺牲设计深度）：深度来自玩家组合而非设计师复杂性。实例：Shapez 2。

Factorio（尤其是含有 Space Age 和社区 Mod 的版本）最接近突破此三角，通过在其所有三层中保持优异表现：它的核心配方是可理解的，其设计深度是由系统交互而非个别配方提供的，而其蓝图和 Mod 系统允许不受限制的涌现潜力。

### 7.3 配方系统作为"游戏引擎"

总结本报告的宏观点：工业自动化游戏中的配方系统不只是特性——它们是**该类型的引擎**。正如物理引擎决定了射击游戏或平台跳跃游戏中的"可能空间"一样，配方系统决定了自动化游戏中的"可能空间"。

- 物料配方引擎 → 解决线性规划和比例匹配问题
- 几何变换引擎 → 解决空间推理和序列规划问题
- 物理模拟引擎 → 解决热力学和系统均衡问题
- 空间物流引擎 → 解决网络流和最小路径问题

下一个重要的工业自动化游戏将可能不是任何一个引擎的新实例——而是**混合多个引擎**。一个既有物料配方深度、又有几何变换可组合性、又有物理涌现性、又有物流空间性的游戏，将定义该类型的新"天花板"。

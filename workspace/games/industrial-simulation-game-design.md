# 游戏原型讨论：基于真实资源的工业化模拟

> 状态：**早期讨论 / 脑暴阶段**
> 日期：2026-07-04（最后更新：同日）
> 标签：`game-design` `simulation` `industrialization` `prototype`

---

## 一、核心愿景

### 1.1 一句话描述

一款模拟经营游戏，玩家如同穿越到奇幻/古代世界，基于**真实资源与化学/物理规则**，从零开始逐步工业化，并最终进入治理层面的决策阶段。

### 1.2 核心体验目标

- **穿越小说的游戏化**：复现"现代人带着知识穿越到古代/异世界，逐步推进工业化"的体验。玩家面对的不是虚拟的"铜矿石"，而是具体的矿物（孔雀石、黄铜矿、斑铜矿……），需要根据矿物的实际化学性质选择处理路线。
- **知识驱动而非科技树驱动**：不做传统的"花费研究点数解锁科技"的设计。玩家有知识就能做，没有知识就不知道怎么做——类似于"你知道湿法炼铜的原理，你就能尝试搭建产线"。
- **分层次的可玩性**：表层是经典模拟游戏的骨架（建筑、物流、人口），深层是可探索的工业细节。类似计算机的抽象层次——你可以用"默认冶炼厂蓝图"，也可以深入优化内部的化学反应流程。

### 1.3 两个阶段

| 阶段 | 焦点 | 核心循环 |
|------|------|----------|
| **一阶段：工业化** | 资源勘探、产线搭建、技术探索 | 采集→加工→生产→扩张 |
| **二阶段：治理** | 指标管理、随机事件决策、社会系统 | 观察指标→应对事件→做出选择→承受结果 |

**最新决策（2026-07-04）**：二阶段留作扩展，大概率作为独立玩法模块或 DLC。一二阶段之间通过抽象思维拆分——不强制融合。另有一个想法是将二阶段的"事件"系统降维为一阶段的**知识发现提示系统**（见 5.1.3）。

## 二、与现有游戏的关键区别

### 2.1 资源系统的真实性

现有模拟游戏的普遍做法：
- 铜矿 = 铜矿石 → 熔炼 → 铜锭。矿物类型单一，技术路线固定。
- 升级科技树 → 解锁更好的熔炉 → 效率从 1x 变成 2x。

我们的想法：
```
实际工业中，不同类型的铜矿有完全不同的处理路线：

氧化铜矿（如孔雀石 Cu₂CO₃(OH)₂）：
  采矿 → 湿法浸出（稀硫酸）→ 萃取 → 电解 → 纯铜
  或：采矿 → 堆浸 → 溶剂萃取 → 电积（SX-EW）

硫化铜矿（如黄铜矿 CuFeS₂）：
  采矿 → 破碎 → 浮选 → 精矿 → 焙烧/熔炼 → 冰铜 → 转炉 → 粗铜 → 电解精炼 → 纯铜

自然铜（罕见，但历史上是最早被使用的铜）：
  直接采集 → 冷锻/加热锻造 → 铜器
```

这意味着玩家在不同地区发现的"铜矿"可能完全不同，处理方式也不同。这也自然地创造了探索价值和地域特色。

### 2.2 不用科技树的替代方案

传统科技树的问题：
- 玩家总是先解锁再建造，缺乏发现的惊喜
- 路线固定，缺少"用不同方式解决同一问题"的空间
- 与"穿越者利用知识"的叙事不匹配

替代思路：
1. **知识即解锁**：玩家（角色）自带/可获取的知识决定能做什么。类似 Outer Wilds 的"知识就是进度"——你知道怎么做，就能做。
2. **规则驱动的涌现**：因为基于真实的物理/化学规则，所以玩家可以发现设计者也没有预想到的生产路线。
3. **实验系统**：允许玩家在小规模上尝试工艺路线，成功后再蓝图化、规模化。失败可能造成资源浪费或事故。

### 2.3 层次化抽象模型（蓝图/集总模型）

这是本设计最核心的差异化机制之一。

**灵感来源**：计算机科学中的抽象层次。CPU 设计者定义指令集架构（ISA），微架构的实现者可以自由优化内部，只要外部接口不变。

**游戏中的对应**：
```
[玩家视角]                    [默认实现]
  炼铜厂蓝图                   基础熔炼线
  - 输入：铜矿石                 破碎机 → 熔炉 → 铸锭
  - 输出：铜锭                  （简单但低效、高污染）
  - 效率：60%                  [可被玩家替换]
  - 人工需求：5人
  - 燃料需求：煤炭               [玩家优化后]
  - 副产物：炉渣                 浮选 → 焙烧 → 浸出 → 电解
  - 占地面积：4x3               （复杂但高效、可回收副产物）
```

**最新决策（2026-07-04）——抽象层次简化**：

```
层次设计（简化版）：
  第一层：城镇地图层
    - 建筑 = 蓝图实例
    - 暴露指标：输入/输出/效率/人口/占地面积
    - 玩家在此层进行宏观布局和资源调配

  第二层：蓝图编辑模式
    - 切换到独立编辑界面（非地图缩放）
    - 内部产线布局、物流连接
    - 类似 Factorio 的产线设计
    - 可保存/加载蓝图

  第三层：工艺层（预留）
    - 单个工艺步骤的参数调整（温度、压力等）
    - 当前不做实现，仅保留数据模型扩展性
    - 未来可作为 DLC 或高级玩家功能
```

关键设计要点：
- 每个"蓝图"对外暴露统一的输入/输出/指标接口
- 设计者提供默认的"足够好"的实现
- 玩家**可以选择**深入蓝图编辑进行优化
- 优化后的蓝图可以在后续游戏中复用（蓝图库）
- 社区可以分享蓝图（类似 Factorio 的蓝图字符串）
- 地图层只暴露**占地面积**指标，不展示内部细节

### 2.4 抽象模型深度剖析：以电力系统为例

电力系统是一个理想的案例来演示抽象层次的设计，因为**电本身是高度纯净的**——指标明确（功率、电压、电流、频率），现实中就有成熟的分层架构（发电→输配电→用电）。

#### 2.4.1 经典模拟游戏的做法

```
[矿脉] → [发电站] → [电线] → [终端设备]
         （可能再加个电池）

特点：
- 能源矿是唯一的燃料（煤/铀/...）
- 发电站只有少数几种（火力/核能）
- 电线不分类型
- 不考虑电压、交直流、损耗
- 电池是唯一的储能手段
```

#### 2.4.2 我们的分层设计

以默认技术路线为例（这是开发者提供给所有玩家的**保底路线**）：

```
地图层视角（第一层）：
  [发电站] ──输电── [变电站?] ──配电── [用电器]
  暴露指标：功率输出、燃料消耗速率、占地面积

默认实现（第二层——蓝图内部）：
  发电站 = 烧开水蒸汽锅炉 + 交流发电机
  输电 = 裸露铜线（交流）
  用电器 = 直接接受交流电
  不使用变电站（默认假设发电机电压=终端需求电压）
  只考虑功率，不考虑电压这个指标
```

**这是所有玩家都能用的默认方案——简单、能用、但远非最优。**

#### 2.4.3 分解发电站：标签驱动的燃料系统

"烧开水"这种发电方式，可以进一步分解为子蓝图：

```
发电站蓝图 = [热量供给] + [蒸汽锅炉-汽轮机-发电机组]

热量供给 — 这是真正有趣的部分：
  只要某个物品具有以下属性标签，就能作为热量来源：
    - combustible: true          （可燃）
    - combustion_enthalpy: N     （燃烧焓，单位 kJ/kg 或 kJ/mol）
    - combustion_products: [...] （燃烧产物列表）

  木材？combustible=true，enthalpy≈15MJ/kg，products=[CO₂, H₂O, ash]
  煤炭？combustible=true，enthalpy≈25MJ/kg，products=[CO₂, SO₂, ash]
  重油？combustible=true，enthalpy≈42MJ/kg，products=[CO₂, H₂O]
  生活垃圾？combustible=true，enthalpy≈8MJ/kg，products=[CO₂, 复杂烟雾]
  氢气？combustible=true，enthalpy≈142MJ/kg，products=[H₂O]  ← 最清洁！

  玩家不需要为每种燃料写一个配方。只要物品携带了这些标签，
  它就可以被"热量供给"子蓝图消费。
```

**核心机制**：标签/属性驱动的配方匹配。不是穷举"木材→烧开水""煤炭→烧开水""重油→烧开水"……而是一条规则——`combustible=true` 的任何东西都能进入 `[热量供给]` 槽位。从少数几条标签规则出发，组合出大量的可能性。

#### 2.4.4 发电模板的多样化

除了烧开水，开发者可以提供其他发电模板（每个都是蓝图接口相同的不同实现）：

```
[热量供给] + [蒸汽循环] + [发电机]   → 交流电 （默认，烧开水）
[热量供给] + [斯特林发动机] + [发电机] → 交流电 （更高效率，但需精密制造）
[光照射]   + [光伏板]              → 直流电 （无运动部件，受天气影响）
[磁场变化] + [线圈]                → 交流电 （水力/风力驱动磁场旋转）
[化学燃料] + [燃料电池]            → 直流电 （高效率，需要纯氢/甲醇）
[核衰变热] + [热电偶]             → 直流电 （RTG，功率低但免维护）
……
```

每个模板对外暴露的接口是统一的（输入能量载体 → 输出电力），内部实现不同。**开发者提供少量经典模板作为起步，更多模板通过 mod 接口由社区贡献。**

#### 2.4.5 输电的多种选择

同一份"把电从 A 送到 B"的需求，可以有不同的传输方式：

```
默认：裸露铜线 + 交流输电（默认电压=终端电压，不考虑损耗）

进阶选项：
  电线类型：铜线 / 铝线 / 超导（需要冷却） / 地下电缆
  电流形式：交流 / 直流
  电压等级：低压 / 中压 / 高压 / 特高压（电压越高损耗越低，但需要变电站转换）
  传输介质：金属导线 / 微波无线输电（需要视距，效率低，但不需要电线杆）
  储能中介：电池运输 / 抽水蓄能 / 压缩空气 / 飞轮

变电站的角色：
  交流↔直流转换（整流/逆变）
  电压变换（升压/降压变压器）
  → 默认实现中不存在，玩家可以深入蓝图添加以优化效率
```

#### 2.4.6 用电器接口：指标的取舍

用电器最简接口只暴露一个指标：

```
最简接口：
  power_consumption: N  (单位：W 或 kW，即 能量/时间)

扩展接口（可选启用）：
  power_consumption: N
  voltage_type: AC | DC    （交流/直流）
  voltage_level: 12V | 110V | 220V | 10kV | ... （电压等级）
  efficiency: 0.0~1.0      （用电效率 = 实际有用功 / 总输入电）

效率的作用——吸收"额外产物"：
  一个电动机效率 0.85，意味着 15% 的输入电能变成了热量。
  这些热量可以不忽略——它进入建筑内部，影响温控系统。
  
  但现阶段，效率可以作为一个"黑洞"参数：
    输入: 1kW 电
    输出: 0.85kW 机械能 + 0.15kW 废热（如果不模拟热，就吞掉）
  
  等到热力系统实装后，废热就不再被吞掉，而是进入热力管网。
  这就是系统之间的耦合扩展。
```

**接口设计原则：指标越少越好，但保留扩展性。**
- 功率是必须的（所有用电器的本质就是消耗功率）
- 电压（交直流+等级）默认可以省略——假设有隐式的转换器，以能量利用效率的折扣替代
- 效率参数统一作为"未追踪产物的黑洞"，未来系统扩展时逐步打开

#### 2.4.7 蓝图的嵌套与组合

电力系统展示了蓝图嵌套：

```
发电站（一级蓝图）
  ├── 热量供给（二级子蓝图）
  │     └── 燃料输入 + 燃烧室 → 热量输出
  ├── 蒸汽循环（二级子蓝图）
  │     └── 热量输入 + 水 → 高压蒸汽
  └── 发电机（二级子蓝图）
        └── 蒸汽动能 + 磁场 → 交流电

输电网（一级蓝图）
  ├── 变电站：升压（二级子蓝图，可选）
  ├── 高压传输线（二级子蓝图）
  └── 变电站：降压（二级子蓝图，可选）

终端用电器（一级蓝图）
  └── [电动机] / [电热器] / [照明] / [电解槽] / …
```

玩家可以：
- 只使用一级蓝图的默认实现（快速游玩）
- 深入任意二级子蓝图进行替换优化（深入游玩）
- 创建新的子蓝图变体并保存（自定义/社区分享）

### 2.5 配方系统与离散模拟模型

#### 2.5.1 统一配方模型

从电力系统案例中可以提炼出一个统一的配方模型。每个用户可操作的设备都是：

```
设备 = 配方（Recipe）

配方 = {
  输入物质:  [ (物质A, 数量), (物质B, 数量), ... ]
  输入能量:  [ (能量形式, 数量), ... ]          // 可选
  条件:      { 温度: ≥N, 压力: ≥M, 催化剂: X, ... }  // 非消耗性
  输出物质:  [ (物质C, 数量), (物质D, 数量), ... ]
  输出能量:  [ (能量形式, 数量), ... ]          // 可选
  效率:      0.0~1.0                           // 全局效率系数
  时间:      N ticks
}
```

**效率参数的特殊作用**：
- 将所有难以追踪的"额外产物"打包吞掉
- 例如：电动机效率 0.85，意味着 15% 的电 → 废热。如果热力系统未实装，就简单消失
- 如果热力系统实装了，废热不再消失，而是作为 `输出物质: [(废热, 0.15kW)]` 进入下游
- **效率不是偷懒，是分阶段的抽象——先让系统跑起来，再逐步打开耦合**

#### 2.5.2 离散时序模拟

所有模拟是离散的，按 tick 推进：

```
每个 tick：
  对于每个设备：
    1. 检查输入槽位是否有充足物料/能量
    2. 检查条件是否满足
    3. 如果满足，推进进度条（进度 += 1/时间）
    4. 进度到 100%：消耗输入，产生输出
    5. 输出进入下游设备的输入槽位（或仓库/电网）
```

类似于 Factorio 的配方系统，但更灵活——同一组输入可以匹配多条配方（对应不同的工艺路线），由蓝图选择走哪条。

#### 2.5.3 基本元素的粒度问题

这是一个需要持续讨论的开放问题：**组合的基本元素划分到什么粒度？**

```
候选分类：

能量形式（相对明确）：
  机械能（动能/势能）、热能、电能（AC/DC）、光能（频率?）、
  化学能（隐含在物质中）、核能……

纯化学物质：
  元素：Cu, Fe, S, O₂, N₂, H₂, Cl₂, Au, Ag, ...
  简单化合物：H₂O, CO₂, SO₂, H₂SO₄, NaOH, NaCl, CuSO₄, Fe₂O₃, ...
  复杂化合物：Cu₂CO₃(OH)₂ (孔雀石), CuFeS₂ (黄铜矿), ...

天然/常见混合物：
  矿石（以主要矿物成分定义 + 脉石/杂质含量）
  空气（N₂+O₂+...）
  海水（H₂O+NaCl+...）
  生物质（纤维素+木质素+水+...）

加工商品（高度抽象，封装内部细节）：
  齿轮、电路板、螺丝、管道、阀门、……
  → 这类物品来自机械加工系统，不是化学反应
  → 但它们是工业产线的必要组件（建设备需要它们）
```

**当前务实立场**：
- 能量形式——明确列举，因为种类有限
- 纯化学物质/常见矿物——以真实的化学式/矿物名定义。这是游戏的核心差异化
- 混合物——以主要成分+杂质含量表示
- 加工商品——第一阶段可能大幅简化。先用一个抽象的"机械零件"代表所有加工品。后续再拆分
- **原则：先以最小可行集合跑通核心循环，再逐步细化**

### 2.6 蓝图模板、知识系统与规则引擎的关系

这三个系统是协同工作的：

#### 2.6.1 三层关系

```
知识系统（第零层+第一层）
  │  玩家知道"湿法炼铜"→ 可以尝试构建对应蓝图
  │  玩家不知道 → 使用默认模板，或通过提示系统逐步发现
  ▼
蓝图系统（模板库）
  │  开发者提供默认模板（如"基础炼铜厂"）
  │  玩家基于知识/实验创建优化变体
  │  社区通过 mod 贡献更多模板
  ▼
规则引擎（配方匹配）
  │  标签/属性驱动的通用规则（如 combustible=true → 可用于热量供给）
  │  开发者手写的经典工艺路线（如"黄铜矿→浮选→焙烧→电解"）
  │  未来愿景：足够多的基础规则产生涌现行为
```

#### 2.6.2 当前务实策略：手写路线为主，标签规则为辅

- **涌现生成是愿景，不是 MVP 目标**。涌现需要足够密集的基础规则网络。
- **开发探索阶段**，由开发者手动加入经典技术路线（铁的块炼法 vs 高炉法、铜的火法 vs 湿法、纯碱的路布兰 vs 索尔维……）
- **标签/属性系统**在 MVP 阶段主要服务于燃料类（可燃物的燃烧焓）、矿石类（矿物成分决定适用的处理路线）等"天然适合标签化"的领域
- **Mod 接口**作为长期的扩展渠道——社区可以添加更多"偏门"工艺路线而不增加核心开发负担

#### 2.6.3 一个具体的例子：从标签到路线选择

```
场景：玩家发现了一种矿石。

知识系统：
  - 有知识的玩家（L3+）：直接认出"黄铜矿 CuFeS₂"，系统给出所有适用路线
  - 无知识的玩家（L0-L2）：经过提示系统逐步发现

标签系统（矿石的属性）：
  mineral_type: sulfide        ← 硫化矿
  metal_content: { Cu: 34.6%, Fe: 30.4%, S: 35.0% }
  associated_minerals: [pyrite, quartz, ...]

规则引擎（路线匹配）：
  所有以 sulfide 为输入的工艺路线自动适用：
    ✅ 浮选 → 焙烧 → 熔炼 → 电解精炼
    ✅ 高压氧浸出（如果玩家有高压设备）
    ❌ 直接湿法浸出（稀硫酸对硫化矿效果差 ← 这是化学事实，不是游戏限制）

  但如果 mineral_type = oxide：
    ✅ 湿法浸出（稀硫酸直接溶解）
    ✅ 直接熔炼（碳热还原）
    ❌ 浮选 → 焙烧（没有硫可烧，不需要浮选脱硫）
```

**关键**：规则引擎不做"哪些工艺研究过了"的追踪（那是科技树的逻辑）。规则引擎只做"这个矿物+这些条件→哪些路线可行"。路线是否可用的唯一限制来自**资源+设备条件**，而非研究点数。

## 三、案例深度分析：铜的工业化

### 3.1 场景设定

玩家在领地里发现了"绿色的石头"（孔雀石露头）。这是穿越者/玩家（带着现代知识）识别出这是铜矿的第一个机会。

### 3.2 可能的处理路线

```
路线A（最简单——直接熔炼）：
  孔雀石 → 破碎 → 木炭加热（~700°C）→ 粗铜 → 铸造成型
  产物：含杂质的粗铜
  工具需求：石锤、土窑
  适合早期、小批量

路线B（中等——湿法冶金）：
  孔雀石 → 粉碎 → 稀硫酸浸泡 → 硫酸铜溶液 → 铁置换 → 海绵铜 → 熔铸
  产物：较纯的铜
  需求：硫酸（如何获得？→ 硫磺燃烧 → SO₂ → 铅室法 → 硫酸，又是一条技术链）
  适合中期、中批量

路线C（进阶——电解精炼）：
  粗铜（阳极）→ 硫酸铜/硫酸电解液 → 纯铜（阴极，99.9%+）
  需求：稳定的电力来源、硫酸
  副产物：阳极泥（含金、银、铂等贵金属！）
  适合后期、大批量、高品质需求

路线D（如果找到的是硫化矿）：
  黄铜矿 → 破碎 → 浮选（需要浮选药剂）→ 精矿 → 焙烧（脱硫）→
  熔炼 → 冰铜（Cu₂S-FeS）→ 转炉吹炼 → 粗铜 → 电解精炼 → 纯铜
  SO₂副产物 → 可制硫酸（回用于路线B/C！）
```

### 3.3 连锁反应与涌现复杂度

上述路线会自然引出以下需求：
- **硫酸的来源**：硫磺矿 → 燃烧 → SO₂ → 铅室法/接触法 → 硫酸（这本身就是一条工业链）
- **铁的来源**（用于置换沉淀铜）：需要铁矿 → 炼铁 → 铁屑
- **电力的来源**（用于电解）：水力？风力？蒸汽机？→ 需要机械加工能力
- **副产物的利用**：阳极泥中的贵金属、SO₂ 制硫酸、炉渣用于建材

这些连锁反应**不是设计者手动设计的科技树**，而是**真实化学的必然结果**——设计者只需要正确模拟化学规则。

## 五、核心设计决策

### 5.1 知识系统（已确定方案）

**✅ 最终方案：B + C 混合，配合默认指引作为保底**

#### 5.1.1 三层知识模型

```
第零层：默认科技路线指引（保底机制）
  - 系统提供基础、默认的工艺路线
  - 不要求玩家有真实世界知识
  - 相当于游戏内置的"基础工艺手册"
  - 但这些默认路线不一定是最优的
  - 轻度玩家可以完全依赖此层进行游戏

第一层：玩家知识即角色知识（方案B）
  - 穿越者带着现代知识——这是叙事核心
  - 不做知识限制，你知道就能尝试
  - 核心挑战是：你有资源实现吗？
  - 有知识的玩家可以跳过默认路线，直接用更高效的方法

第二层：基于资源的软锁定（方案C）
  - 知识不是瓶颈，资源才是
  - 电解铜需要稳定的电力——在你有发电机/水电站之前做不到
  - 湿法冶金需要硫酸——在你有硫磺矿和铅室法之前做不到
  - 这形成了自然的"时代/纪元"划分：
    石器时代 → 铜器时代 → 青铜时代 → 铁器时代 → 工业时代 → ...
  - 每个时代的跨越由关键资源/基础设施的获得驱动，而非"点科技树"
```

#### 5.1.2 时代/纪元划分（资源驱动）

时代划分由**关键基础资源的掌握**决定，而非研究点数：

| 时代 | 标志性资源/能力 | 解锁的典型工艺 |
|------|----------------|---------------|
| **石器时代** | 石头、木材、骨头 | 基础工具、土窑、木炭 |
| **铜器时代** | 自然铜/氧化铜矿、木炭 | 直接熔炼、冷锻、铸造 |
| **青铜时代** | 铜+锡/砷矿石 | 合金熔炼、模具铸造 |
| **铁器时代（早期）** | 铁矿石、木炭、石灰石 | 块炼铁（Bloomery）、锻造 |
| **铁器时代（进阶）** | 铸铁、炒钢、水力鼓风 | 高炉、精炼（Finery/Puddling） |
| **化学工业时代** | 硫酸（铅室法）、纯碱（路布兰/索尔维） | 湿法冶金、大规模化工 |
| **电气时代** | 稳定电力、电解技术 | 电解精炼、电化学工业 |
| … | … | … |

#### 5.1.3 知识发现提示系统（二阶段降维）

当玩家**不知道**某种矿物/工艺时，系统通过渐进式提示帮助发现：

```
提示层级：

L0 - 文字传闻
  "有商队提到，在南山那边见过一些绿色的石头"
  → 玩家无法直接使用，但知道有东西存在

L1 - 实物描述
  "你亲眼见到了那种石头：表面有绿色和蓝色的斑纹，质地较软"
  → 玩家（如果知道孔雀石特征）可以尝试识别
  → 或者经过足够多次的接触，系统给出鉴定结果

L2 - 工匠分析
  "铁匠将其投入火中，发现会发出绿色火焰，冷却后得到红色的金属"
  → 系统确认这是铜矿，给出基础的直接熔炼路线

L3 - 完整但不最优的工艺
  "经过长期实践，工匠们掌握了从这种石头中提取铜的方法"
  → 系统给出完整但效率不高的默认工艺路线
  → 玩家可以在此基础上优化

捷径：如果玩家有足够知识
  "你立刻认出这是孔雀石（Cu₂CO₃(OH)₂），一种氧化铜矿"
  → 直接解锁所有适用于氧化铜矿的工艺路线
  → 可以马上开始设计和实验
```

**设计意图**：这个提示系统既保留了"发现"的乐趣，又不会把无知识的玩家卡死。有知识的玩家获得"穿越者红利"——一眼认出矿石、直接跳过发现阶段。

### 5.2 抽象层次（已确定方案）

详见 2.3 节。

## 六、历史工艺参考：多路径生产的经典案例

### 6.1 案例一：铁的冶炼——东西方两条路线

这是历史上最经典的"同一目标，不同路线"案例，完美契合游戏设计理念。

```
目标：从铁矿石中获得可用的铁/钢

路线1：直接法（块炼铁 / Bloomery）——西方路线
  铁矿石 + 木炭 → 块炼炉（~1200°C，固态还原）→ 海绵铁块（bloom）
  → 反复锻打除渣 → 熟铁（wrought iron, C<0.03%）
  → （可选）渗碳 → 钢（0.4-0.8% C）
  
  特点：
  - 不熔化铁（纯铁熔点 ~1538°C，达不到）
  - 渣含量高（1-3%），需要大量锻打
  - 小批量（5-30 kg/炉），间歇操作
  - 产品不均一：同一块 bloom 中可能同时有熟铁和钢
  - 适合分散的、小规模的铁匠经济
  - 欧洲、地中海、近东、非洲的主流工艺（~1000 BCE 到中世纪）

路线2：间接法（铸铁 → 脱碳）——中国路线
  铁矿石 + 木炭/焦炭 → 高炉（~1150°C+，液态）→ 铸铁（C=2-4%）
  → 退火脱碳（固态，700-1000°C，氧化气氛）→ 可锻铸铁/钢
  或 → 炒钢（液态，搅拌氧化脱碳）→ 钢/熟铁
  
  特点：
  - 铁完全熔化，渣浮于铁水上，分离干净
  - 连续操作，可大规模生产
  - 铸铁可直接铸造成型（复杂形状，一次成型）
  - 需要大型高炉、强力鼓风（水力/畜力）、大量资本
  - 适合中央集权的、国家规模的工业
  - 中国从公元前6-5世纪就已掌握，比欧洲早 ~2000 年

关键洞察：
  两条路线的差异不是因为"谁更聪明"，而是社会结构的不同：
  - 中国有青铜铸造传统（高温炉、陶范）→ 直接跳到高炉
  - 中国有中央集权（汉朝铁业官营）→ 能动员资本建大高炉
  - 欧洲分散的铁匠经济 → 小高炉、灵活、但效率低

游戏应用：
  → 玩家的初始条件（社会组织形式、可用资源、已有的相关技术）
    会影响能走的路线
  → 同一个"炼铁"目标，不同玩家可能有完全不同的体验
```

### 6.2 案例二：纯碱（碳酸钠）——四种工业路线

纯碱（Na₂CO₃）是工业化的基础化学品（玻璃、肥皂、造纸、纺织），其生产工艺经历了多次路线更替，是另一个"多路线"的完美案例。

```
目标：获得纯碱（Na₂CO₃）

路线1：天然碱（古代～至今）
  天然碱湖/碱土 → 浸取 → 蒸发结晶 → 粗碱
  或：海草/木材 → 焚烧 → 浸取 → 钾碱（K₂CO₃，类似用途）
  
  特点：零工业基础即可，但产量受限于自然资源

路线2：路布兰法（1791 ~ 1918）
  NaCl（食盐）+ H₂SO₄（硫酸）→ Na₂SO₄（盐饼）+ HCl↑（污染！）
  Na₂SO₄ + CaCO₃（石灰石）+ C（煤）→ 高温熔融 → Na₂CO₃ + CaS（废渣）
  
  特点：
  - 第一种合成纯碱工艺
  - 需要硫酸（→ 需要硫磺和铅室法）
  - 污染严重（HCl 气体、CaS 废渣）
  - 劳动密集
  - 但推动了整个化学工业的发展（硫酸工业、副产物回收）

路线3：索尔维法 / 氨碱法（1860s～至今，占全球 ~75% 合成纯碱）
  NaCl（盐水）+ NH₃（氨）+ CO₂ → NaHCO₃↓（碳酸氢钠沉淀）
  NaHCO₃ → 加热 → Na₂CO₃ + CO₂↑ + H₂O↑
  氨回收：NH₄Cl + Ca(OH)₂ → NH₃↑ + CaCl₂（副产物）
  总反应：2NaCl + CaCO₃ → Na₂CO₃ + CaCl₂
  
  特点：
  - 连续操作、成本低
  - 氨循环使用（核心创新！）
  - 比路布兰法清洁
  - 需要廉价的氨 → 哈伯-博斯法（1913）使氨变得廉价

路线4：侯氏制碱法（侯德榜，1930s～至今，中国 ~27% 合成纯碱）
  索尔维法的变体：
  NaCl + NH₃ + CO₂ + H₂O → NaHCO₃↓ + NH₄Cl
  NH₄Cl 不作为废物回收氨，而是直接作为氮肥出售
  利用合成氨厂的废 CO₂
  
  特点：
  - 不产生 CaCl₂ 废料（索尔维法的主要废料）
  - 联产氮肥（NH₄Cl）
  - 需要与合成氨厂联合

关键洞察：
  1. 路布兰法虽然被淘汰，但它在当时是革命性的——它使纯碱不再受天然资源限制
  2. 索尔维法的核心创新是"氨的循环回收"
  3. 哈伯-博斯法（合成氨）是另一个技术 → 它使索尔维法更经济
     → 技术之间的相互依赖关系
  4. 侯氏法利用了合成氨厂的废 CO₂，变废为宝
  → 玩家可能发现设计者未预料的"跨工艺副产物利用"

游戏应用：
  → 不同的起始条件可能导致采用不同的制碱路线
  → 有天然碱湖？直接用天然碱
  → 有硫磺矿？考虑路布兰法
  → 已有合成氨厂？索尔维法或侯氏法
  → 副产物的利用可以串联不同的工业链
```

### 6.3 案例三：硫酸生产——工业的血液

硫酸是"工业的血液"，有多种历史生产路线：

```
路线1：干馏绿矾（古代～18世纪）
  FeSO₄·7H₂O（绿矾）→ 加热干馏 → H₂SO₄（发烟硫酸）+ Fe₂O₃
  最早的方法，产量极低

路线2：铅室法（1746～20世纪）
  硫磺 + KNO₃（硝石，氧化剂）→ 在铅室内与水反应 → H₂SO₄（~78%）
  需要硝石（智利硝石或粪硝）
  产量大但仍有限制

路线3：接触法（19世纪末～至今，占全球 ~99%）
  硫磺/黄铁矿 → 燃烧 → SO₂ → V₂O₅催化剂氧化 → SO₃ → 浓硫酸吸收 → H₂SO₄（98%+）
  纯度极高，可生产发烟硫酸
  需要钒催化剂（1910s后）
```

**游戏应用**：硫酸是湿法冶金的必需品，而硫酸本身又有多条生产路线。玩家能否获得硫酸，取决于他们能找到什么资源（硫磺矿？黄铁矿？绿矾？硝石？）。

## 七、技术可行性初步评估

### 7.1 模拟引擎

核心挑战是实现一个**基于规则的化学反应/物理模拟引擎**。

- 不需要真正做 CFD 或量子化学计算
- 需要的是**图变换系统**：输入物质 + 条件 → 输出物质 + 副产物
- 每个反应规则包含：反应物、产物、条件（温度、压力、催化剂等）、速率
- 可以借鉴 Factorio 的配方系统，但更灵活——同一组输入可以有多条反应路径

### 7.2 实现难度分层

| 系统 | 难度 | 说明 |
|------|------|------|
| 基础建筑/物流网格 | ⭐⭐ | 成熟的模式，大量参考 |
| 物品/配方系统 | ⭐⭐ | Factorio-like，成熟 |
| 蓝图编辑模式 | ⭐⭐⭐ | 独立 UI 视图的设计是核心难点 |
| 蓝图抽象接口 | ⭐⭐ | 简化为输入/输出/指标的数据模型 |
| 化学反应规则引擎 | ⭐⭐⭐⭐ | 需要设计可扩展的规则系统，需领域知识 |
| 知识系统（B+C模型） | ⭐⭐⭐ | 时代划分 + 提示系统 + 默认工艺手册 |
| 知识发现提示系统 | ⭐⭐ | 事件触发 + 条件检查 + 渐进信息揭示 |
| 工艺参数层 | ⭐⭐⭐⭐ | 预留，不做实现 |
| 治理事件系统 | ⭐⭐ | 预留，远期扩展 |

### 7.3 技术选型

**✅ 纯前端 Web 技术**

- 快速迭代，关注核心玩法而非画面
- Canvas 2D 或 DOM-based grid
- 数据驱动：反应规则、矿物属性、配方等全部 JSON/YAML 配置
- Mod 友好：从一开始就考虑数据接口的扩展性

### 历史工业参考
- **铁的冶炼**：块炼铁（西方直接法）vs 铸铁脱碳（中国间接法）——社会结构影响技术路线的经典案例
- **纯碱生产**：天然碱 → 路布兰法 → 索尔维法 → 侯氏制碱法 ——四代工艺更替与技术杂交
- **硫酸生产**：干馏绿矾 → 铅室法 → 接触法 ——催化剂改变工业格局
- 铜的湿法冶金（SX-EW）vs 火法冶炼（浮选+熔炼+电解）
- 哈伯-博斯法合成氨 ——一个技术如何解锁多个下游工艺

### 参考概念
- 计算机体系结构中的**抽象层次**（ISA → 微架构 → 电路）
